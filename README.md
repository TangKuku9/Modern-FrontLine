# 现代战线 MODERN FRONTLINE

一款在浏览器里运行的现代军事题材第一人称射击游戏（原创致敬作品），用 Three.js 写成，**没有用到任何外部美术或音频素材**：所有纹理（包括法线和粗糙度贴图）、模型和音效都由程序实时生成。

## 开发背景

本游戏全程仅通过 **Claude Opus 5.5** 的**一轮对话**生成完成。

- 实机游玩视频：[B 站 BV1poaP6YEKy](https://www.bilibili.com/video/BV1poaP6YEKy)

## 运行方法

游戏使用 ES Module，必须通过本地 HTTP 服务器打开，直接双击 html 文件打不开：

```bash
cd mw
python3 -m http.server 8080
# 然后在浏览器打开 http://localhost:8080
```

推荐使用最新版 Chrome 或 Edge，并开启独立显卡。如果帧数偏低，可以在「设置」里调低画面质量。

## 内容

### 战役：行动代号「午夜清道夫」
夜间渗透卡尔达什边境，和布雷克上尉、狙击手渡鸦组成三人小队，共 7 个阶段：
1. 夜视仪渗透（按 N 切换夜视仪）
2. 清除前哨站。可以选择潜行：敌人有「警觉值」，发现你需要一段时间；蹲伏和使用消音武器都更难被发现，被察觉后整组敌人会一起警戒
3. 穿越村庄
4. 突入大院，逐屋清理，击毙高价值目标「铁蝎」
5. 按住 F 下载情报
6. 坚守 90 秒，抵挡三波敌方增援（包括皮卡运兵）
7. 东门打开，乘直升机撤离

其他：设有检查点，死亡后按空格从检查点重来；可选三档难度，并记录最佳通关时间。

### 多人对战（对战 AI）
- **模式**：团队死斗、占领（A/B/C 三个据点）、自由混战
- **地图**：
  - 沙丘镇：沙漠，白天
  - 寒霜炼厂：暴风雪
  - 霓虹街区：雨夜都市
  - 货柜场：黄昏港口
- **AI**：分三档难度，会寻路、找掩体、投雷、夺点，也会使用连杀奖励
- **Perk**：3 个栏位共 12 项，包括双倍时间、拾荒者、爆破专家、冷血、强硬路线、火力过载、幽灵、速愈、快手、振奋、静步、高度警觉
- **连杀奖励**：侦察无人机、集束空袭（手动标记目标）、哨戒机枪、武装直升机、白磷弹；每次从中选 3 项
- **计分**：有击杀奖章（爆头、远距离、双杀、三杀、首杀）、助攻，以及经验值和等级系统
- **另一种"多人"**：主菜单里的「联网对战」跑在真对局服务上（见下面《实时联机与云端部署》）。上面这套模式与连杀奖励目前只在打 AI 时完整生效 —— 联网侧只做到"同一间房里的人互相能打死、服务端裁决"，模式规则重做还在下面的清单里。

## 实时联机与云端部署

### 本机先跑起来

```bash
npm install                 # 只有两个运行时依赖：ws、three
npm start                   # http://127.0.0.1:8090/  同一个端口发静态资源 + 跑 WebSocket
```

主菜单 → **联网对战** → 填呼号、选阵营、（可选）房间号 → 加入对局。不带房间号时由服务端
把人往人最少的那间塞。想开两窗对打：第二窗选别的阵营，或两窗填同一个房间号。

也可以直接给 URL（测试和多开的快捷办法，效果与大厅里点一样）：`http://127.0.0.1:8090/index.html?online=1&room=xxx&name=乙&team=B`。
地图与模式由服务端的环境变量决定（见下表），大厅不假装能选它。

### 环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `PORT` | `8090` | 监听端口（也支持 `node server/net-server.mjs 8090`） |
| `HOST` | `0.0.0.0` | 绑定地址；只走本机反代时可收 `127.0.0.1` |
| `NODE_ENV` | — | `production` 才启用静态资源白名单（等价开关：`--prod`） |
| `MAP` / `SEED` | `yard` / `20260925` | 该实例跑的地图与玩法随机流种子 |
| `MAX_ROOMS` | `32` | 每进程房间数上限（一间 = 一份完整 sim） |
| `MAX_CLIENTS` | `128` | 每进程真人连接上限 |
| `MAX_PAYLOAD` | `65536` | 单个入站帧字节上限（正常一帧 ≤ 13×60 = 780 B） |
| `ALLOW_ORIGIN` | 空=不检查 | 逗号分隔的允许来源，**生产务必设** |
| `ROOM_IDLE_MS` | `60000` | 空房间多久回收 |
| `STATIC_MAX_AGE` | `86400` | 非 html 静态资源的 max-age |
| `SHUTDOWN_GRACE_MS` | `4000` | 收到 SIGTERM 后留给收尾的时间 |

### 带宽与 CPU

- 下行快照定长：头 11 B + 每人 25 B。16 人 @20Hz 时**每个客户端 65.8 kbps**（`node server/codec.mjs` 自己印出来，改字段会变）。
- 上行输入 13 B/拍/人，攒一渲染帧一个包发。
- 容量是压出来的，不是算出来的：`npm run soak`（阶梯 16 → 128 人，最后一档可 `node server/soak.mjs 16` 压到 256 人）。
  读数以**服务端自报**为准（`/healthz` 逐间给 hz / 每拍耗时 / 落后墙钟毫秒），因为假客户端跑在压测进程里，
  从对面数出来的帧率分不清是服务器慢还是压测机自己慢。

  本机（Windows，单进程）实测：

  | 人数 | 间数 | 每间 hz | 每拍耗时 | 落后墙钟 | 下行/人 | 峰值堆 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 16 | 1 | 60.1 | 0.125 ms | 0 ms | 20.0 Hz | 15.7 MB |
  | 64 | 4 | 59.9 | 0.083 ms | 0 ms | 20.1 Hz | 26.5 MB |
  | 128 | 8 | 59.3 | 0.064 ms | 0 ms | 20.0 Hz | 25.0 MB |
  | 256 | 16 | 59.1 | 0.060 ms | 0 ms | 20.1 Hz | 36.5 MB |

  256 人这一档**仍然没到模拟的瓶颈**（每拍 0.06 ms，预算 16.7 ms），也就是说再往上先到瓶颈的更可能是
  网络写出与压测进程自己，而不是这份 sim。压完房间被回收后堆回落到 20 MB，长跑不会只涨不落。


### 反向代理

TLS 交给 nginx/Caddy，`wss` 需要显式转发 Upgrade 头，否则浏览器握手会直接失败：

```nginx
location / {
  proxy_pass http://127.0.0.1:8090;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
  proxy_read_timeout 120s;          # WS 空闲期，别用默认 60s 把连接掐掉
}
```

设了 `ALLOW_ORIGIN=https://your.domain` 之后，别的站点就借不走你的对局服务（WebSocket 不受 CORS 约束，不检查来源等于对所有网站开放）。

### 容器与下线

```bash
docker build -t mw-room .
docker run -d -p 8090:8090 -e ALLOW_ORIGIN=https://your.domain mw-room
```

- 健康检查：`GET /healthz` → `{ok, rooms, clients, tickHz, uptime, draining, heapMB, per[]}`；`per[]` 逐间报 `hz / stepMs / behindMs / fails`，扩容时看的是"哪一间先吃紧"，`fails` 在"一个客户端的坏数据打死一屋子人"之前就会先动。Dockerfile 里已挂 HEALTHCHECK。
- 下线：收到 `SIGTERM` 后先置 `draining`（`/healthz` 里能读到，LB 可据此摘实例），给在册连接发一条带原因的 `note` 并以 `1001` 关闭，停掉房间循环，在 `SHUTDOWN_GRACE_MS` 内退净。
- ⚠ **上面这两条 docker 指令在这台开发机上没有构建验证过**：本机没装 docker。已验的是 `CMD`/`HEALTHCHECK` 依赖的那两条运行时事实（`node server/net-server.mjs` 的启动与 `/healthz` 读数、`SIGTERM` 走的是同一份 `shutdown()`），镜像本身要在有 docker 的机器上 `docker build` 一次才算数。
  ⚠ 这一段在 Windows 上**没被测过**：libuv 的 `child.kill()` 是直接 TerminateProcess，信号送不进子进程。Linux 上由 `server/deploy-probe.mjs` 的三条断言验收。

### 验收（改这套代码之前先看它绿不绿）

```bash
npm test          # 不含浏览器：gate + rollback + net-journal + net-probe + deploy-probe + xenv + fps + viewmodel
npm run test:all  # 再加两个真浏览器测试（net-play 对打、net-drop 掉线，要下载 playwright 浏览器）
```

- `server/deploy-probe.mjs` 61 项：静态白名单（含 `/server/*.mjs`、`/.git/config` 拿不到，且 dev 模式仍可取，证明拦网会 Discriminate）、ETag/304、gzip 往返一致、路径穿越、来源检查两个方向、超帧被断且**别人那一局不陪葬**、房间配额、自动分配、空房回收、优雅下线；外加进场装备闸门（21 条：五套预设职业原样通过 + 未知枪 id/未知配件/越权副武器/无限手雷数全被筛掉 + 端到端"恶意载荷进来之后这间还在 60Hz、旁观者一秒没停"）、心跳清理的两个方向（不回 pong 的连接 15~26 秒内被拆；刚建立沉默 9 秒的不许被拆）。
- `test/rollback.mjs` 79 项：回滚重放与顺跑逐位相同（12 个 ack 点 × 46 字段）+ 七条反证臂。其中四组是历轮新立的：**C5 两代回滚**（证明"上一代纠正过的账本要写回去"，一代回滚读的是原始草稿、永远看不出账本过期）；**C6 首段空跑**（服务端一步二选一，"空跑落在首次消费之前"那几拍 `rep` 报不出来 —— 参照是一次把服务端真实输入序列展开的独立顺跑，旧通路差 0.1447 m、新通路逐位重合）；**C7 同一拍连拽三次**（饥饿窗里 ack 不动，真浏览器里实测 71 包都是这个形状；判据是幂等 + "这一格的账本对象不许被换掉"，注入老写法立刻 0/0.0855/0.1000 m 三代递增）；以及**每实体私有流**（证明"旁边有人开火不许挪动我的后坐"，判据两向：B 的私有流游标与 yaw 逐位不变，再用总抽数 18/36 反证同场真有第二个人在抽数）。
- `test/net-play.mjs` 29 项：两个真浏览器对打 —— 移动复制、跨窗口击杀由服务端裁决、重生、武器一致、拍号契约。三条新立的结构判据：基态旗标与权威端逐位一致（编码表和**取值方式**两边同源，且比的是**重建出来那一刻**的姿态，不是账本那一格，`rep=0` 的稳态包才可比）；"折叠拍缺口是一次性的"（单窗 ≤ 一份快照 3 拍，不许随快照累积）；以及**空跑窗的残差小于"我自己走一拍"**（尺子是客户端自己量的日记本相邻两拍距离，不是米数阈值 —— 补偿漏掉时残差恰好等于 `deficit` 拍，`deficit≥1` 就跨过尺子）。
- `test/net-drop.mjs` 40 项：掉线要"看得见"，外加联机入口真在菜单里。四种情形分开验收 —— 连接被关（onclose → 'closed'）、半开连接（2.5 秒没快照 → 'stale'，用只掐下行不掐 socket 的方式复现）、进场被拒（welcome 之前的 err → 加载页写明原因，且那句不是我们猜的"连接超时"）、存档被手改坏（不存在的枪 id 不许把页面打死，玩家身上那份必须是服务端回声的**那个对象**）。世界会暂停、横幅不自动淡、Enter 重连。E 段从主菜单一路点到局内 —— 走的就是玩家真会走的那条路，视口也给 1280×720（480×270 下菜单滚不到按钮，那种尺寸只会量到视口，量不到入口）。
  - 这一段顺手抓到一次"连接刚建立就被单方面拆掉（1006、wasClean=false）"：判据是 `net.closedInfo`，成因在服务端心跳 —— 老写法按"这轮扫描时标志位"判死，事件循环被建房/GC 拖住几秒就会误杀健康玩家。现在按"上一次收到 pong 的时刻"判，并留了一行 `[hb]` 日志。
- `server/xenv.mjs`：跨环境一致性。判据在 2026-09-26 从"整场逐位全等"改成了**由引擎指纹自校准的两档**，因为前者把"两台引擎恰好实现相同"当成了这份代码的正确性判据 —— 结果红是常态，红灯就被无视了。指纹每次运行都实测（每个数学函数 3 万次调用结果的双精度位模式）：本机 Node V8 12.4 vs Chrome/153，`sqrt/hypot/乘加` 逐位相同（规范要求精确舍入），而 `sin cos tan atan2 asin acos pow(0.8) exp log cbrt` 共 11 个逐位不同（规范只要求"实现近似"）—— 而 `sin/cos/atan2` 正是"朝向→移动方向"用的，`pow(x,0.8)` 正是爆炸伤害用的。于是：**指纹全同时仍要求逐位全等**（此时任何分歧都是这份代码的 bug）；**指纹有异时改判三条结构性性质**（单飞 300 拍逐位全等 / 世界几何签名逐采样点相同 / 累计玩法抽数相等），并印出分歧形状。实测档 2：首分歧第 760 拍，91 个采样点世界签名全同，累计抽数 1624 == 1624，逐拍错拍 73/900（总量 12.2%、单拍最大 19）—— **错拍而总量不变**，这是"离散事件被挪了一拍"的签名，不是分支分叉（后者会让累计抽数不等，那才是真 bug）。

### 还没做完的部分（部署前请看一眼）

1. **账号与存档**：进度/配装仍写在浏览器 `localStorage`，换台机器就没了，也没有身份。**进场装备已经由服务端按表重建**（未知枪 id、非法配件、"火力过载"规则、客户端塞的手雷数全都进不去，见 `js/loadout.mjs`），存档被手改坏也不会再把页面打死 —— 但仍然没有身份，所以"是不是本人发的拍号"之外的事（自瞄、改自己那一侧的模拟）服务端看不见。要做反作弊，先要有账号。
2. **延迟补偿命中判定**：目前服务端用"当下"的位置裁决 hitTest，高延迟下会出现"我明明打中了"。要做 lag compensation（按快照回溯重放射线）。
3. **预测精度（已收口：net-play 那条红线现在绿；这一节留档，没有待办）**：
   **已修 ①（账本写回）**：回滚重放过去只把"人"算回来、没把算出的状态写回日记本，于是账里那些
   拍一直是纠正之前的预测草稿；下一次回滚只要落回同一批拍，就把上一次的纠正整个作废，同一笔位移
   被反复重犯。症状是权威端读数沿同一条路径常数超前我一段、方向一致、每次等长（实测反复出现
   `Δpos≈[-1.187,0,-0.62]`，且客户端补演高达 3282 拍/把）。写回之后：拍号最优 offset 分布从
   `{0:499,1:3,…,7:4}` 变成 **`{0:567}`、错拍 0 包**，补演 3282 → 54 拍，稳态最大 1.34 m →
   多数轮 0.02~0.07 m。守卫是 `test/rollback.mjs` 的 C5 **两代**回滚（一代回滚读的是原始草稿，
   永远看不出账本过期），并做过注入对照：把写回短路掉 C5 立刻红，撤掉注入全绿。
   后来发现**同一处还有第二笔账**：`win[0].j = pl.journal()` 那一行写在权威覆盖**之后**，而那一刻
   `pl` 已经是被补演过 `rep` 拍、又被权威读数覆盖过的状态 —— 把它记进标着 `start` 的那一格，
   等于每次回滚都把账本整体往前挪 `rep` 拍，下一次从这一格出发再补一遍，就再超一遍。实测的形状
   正是"误差 ≈ `(rep − 3)` 拍位移"，只在饥饿窗口出现（`rep=0` 时两者同一时刻，写回是恒等变换）；
   证据是 net-play 打印的现场：`traj[0]`（这一格的位置）**恒等于** `auth`（权威读数），而两者
   按定义本该差 `rep` 拍。删掉这一行（正确的写法就是**不写**：`start` 那一刻的状态已经在
   `applyJournal` 里恢复过，权威读数给的是 `start+rep` 那一刻的，对它没有新信息）之后：
   稳态最大 0.4415 → 0.1492 m，`repForgotten` 176 → 0，补演 3396 → 54 拍。守卫是 C7。
   **同一轮还撤回了 b3e25b6 对 `rep` 的改法**（那是在上面这个洞没找到的时候打的补丁，教训是
   "别为了让红变绿去改计数器"）：把归零点挪到广播之后，持续饥饿时每份快照只报这一窗的 3 拍、
   而客户端每拍都从同一个基态重算，偏差就按 0.2236 m（= 4.46 m/s × 3 拍）为单位一路累积到 1.56 m。
   恢复"ack 之后的末尾连拍"，并把守卫改成判**形状**而不是判有无：单窗缺口 ≤ 一份快照拍数，
   超了就是在累积必须红（当前实测缺口 1~2 拍）。这条形状判据现在同时是"首段空跑补偿到位"的读数。
   **已修 ②（首段空跑，本轮）**：上面那条修完之后剩下的唯一红线是 0.1539 m，归因很清楚 ——
   服务端 `step()` 每步**二选一**：队列有货就消费一条、没有就拿手里那份空跑（`server/room.mjs`）。
   所以两包之间它跑的 `dTick` 步里，空跑可以落在**消费的前面**；而随包的 `rep` 只报"**末尾**连拍"，
   这几拍它报不出来。客户端当时的基态 `journal[ack+1]` 已经把那些消费算进去了，只把 `rep` 补在
   末尾 ⇒ 那几个空跑被排到了消费之后。输入不交换，位置就差整整 `deficit = Δtick − Δack` 拍：
   实测 `0.1539 m ÷ 2 拍 = 0.0770`，而 `4.46 m/s ÷ 60 = 0.0743`，且 `Δpos=[-0.134,0,-0.075]`
   与相邻两拍的差分同向 —— 是"少走了两拍"，不是物理分叉。
   修法：把基线整个挪到 `start − dAck`（= 上一包的 `ack+1`），然后按服务端实际顺序重演
   **lead 拍空跑 → 那 dAck 条真输入 → rep 拍空跑**，总拍数 = `lead + dAck + rep = dTick`，一步不多
   一步不少（`js/net/predict.mjs` 的 `opts.carry`）。`lead` **不需要协议加字段** —— 上一包随快照
   下来的 `rep` 就是"进这一窗之前已欠下的空跑数"，本窗首段 = `deficit − rep`，两项客户端都量得到。
   实测：稳态最大 0.1539 → **0.0109 m**（那族样本 0.1492 → 0.0039 m，判据线 0.12 m）。
   注意它是**逐轮有波动**的，别只记最好那一轮：同日另一轮是 0.0640 m（样本 630）——
   两轮都在判据线的一半以下，而修之前是 0.1539 / 0.4415 这种会压线的量级。
   空跑窗残差最大 0.0055 m、超尺子 0 个，`test/rollback.mjs` 的 C6 在对照里把两条件分开量：
   旧通路 0.1447 m、新通路逐位重合。net-play 为此新立一条量判据：**空跑窗的残差必须小于
   "我自己走一拍"**，尺子是客户端自己量的日记本相邻两拍距离（补漏则残差恰好等于 `deficit` 拍，
   `deficit≥1` 就跨过尺子）。
   这条线**没动过判据线**：0.12 m 仍是 0.12 m，红是修代码修掉的红，不是挪阈值挪掉的。
   残留（已立账，量小）：`dAck ≥ 2` 且空跑夹在两次消费**中间**那种窗形，`lead` 只能把它排在前面，
   而它实际排在中间 —— 差别是"那一点上施加的相邻两拍输入"，对按住不放的走位是零、对正在转视角的
   一拍是亚厘米级。它不可从 `(dTick, dAck, rep, lastRep)` 里分辨出来（要分辨得再要一个字节），
   由上面那条"残差 < 一拍"的判据兜着：超了就红。
   顺带撤回一条**错误归因**：前几轮把这一族说成"补演用的玩法流游标取错了时点（下行里的 `rngState`
   晚了 6~9 拍）"，并据此论证"要么协议 +4 B/实体/快照下发基态游标，要么改折叠拍的手感语义"。
   实测把这个前提否掉了 —— 试过下发基态游标，偏差反而涨到 0.9673 m 且呈 `(rep−3)` 拍线性，
   而"基态游标与客户端日记本里那一格不同"的比例只有 `1/740`：**那个 4 字节是摆设**，因为
   `journal` 从对齐那一刻起就没漂。真正的成因是上面那个"空跑排在消费前面"，`lead` 三项全是
   客户端量得到的量。
   还要把它与下一段的跨引擎分叉区分清楚：这一族是**这份代码**的问题，跨引擎分叉是**引擎**的问题
   （规范允许的实现差异）—— 两者都曾让 0.44 m 这个量级出现，但修法毫不相干，别混成一个数看。
   还有条跨引擎事实值得部署前知道（这一轮把它量实了，并顺手修掉了两个把排查带偏的量具缺陷）：
   **Node 与 Chrome 的 sim 不可能逐位一致，这是规范允许的，不是 bug。** 证据是 `server/xenv.mjs`
   开头的引擎指纹 —— 每函数 3 万次调用的双精度位模式，本机 Node V8 12.4 vs Chrome/153：
   `sqrt/hypot/乘加` 逐位相同（规范要求精确舍入），而 `sin cos tan atan2 asin acos pow(0.8) exp log cbrt`
   共 11 个逐位不同（规范只要求"实现近似"）。`sin/cos/atan2` 是"朝向→移动方向"，`pow(x,0.8)`
   是爆炸伤害 —— 所以两台引擎从某一拍起必然分叉，且换一个浏览器版本就会换个拍号重来。
   实测那场 900 拍：首分歧第 **760** 拍，逐拍错拍 73/900，但**累计抽数 1624 == 1624** ——
   是"离散事件被挪了一拍"，不是分支分叉。世界几何两端是同一份（54 个碰撞体、位置签名一致）。
   这条对部署是好消息：只有服务端（Node）跑权威 sim，浏览器是每 20Hz 被校正一次的客户端，
   跨引擎分叉只表现为"客户端预测的误差下限"，不会让两边状态永久错开。
   两处量具缺陷一并修掉：① 指纹第一版写了 `Math.round(v * 1e9)`，那等于亲手把 ULP 差异抹掉、
   制造出"两台引擎一致"的假象；② `diffTraces` 把**采样点序号**当成了**拍号**报 —— 对局轨迹每
   10 拍才存一个样本，所以它报的 `tick=76` 其实是第 760 拍（本节先前"第 14 拍 / 第 76 拍"
   两处都受这个错标签影响，排查时对着假拍号找过一圈）。
   另外 `js/player.js` 注释里承诺的日记本覆盖率守卫 `test/net-journal.mjs` 从来不存在，补上后
   第一次跑就点出 `dmgMul / loadout / vm` 三个字段没登记归属。
