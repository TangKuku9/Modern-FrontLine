# 现代战线 MODERN FRONTLINE

浏览器里运行的现代军事题材第一人称射击（原创致敬作品），Three.js 写成，**不使用任何外部美术或音频素材**：纹理（含法线、粗糙度贴图）、模型、音效全部由程序实时生成。

- 全程仅通过 **Claude Opus 5.5** 的**一轮对话**生成。实机游玩视频：[B 站 BV1poaP6YEKy](https://www.bilibili.com/video/BV1poaP6YEKy)

## 运行

游戏用 ES Module，必须经 HTTP 打开，双击 html 打不开：

```bash
python3 -m http.server 8080          # 单机：http://localhost:8080
npm install && npm start             # 联机：静态资源与 WebSocket 同端口 http://127.0.0.1:8090/
```

运行时依赖只有 `three` 与 `ws`（Node ≥ 20.10）。推荐最新版 Chrome / Edge 并启用独显；帧数偏低可在「设置」里降画面质量。

## 内容

### 战役：行动代号「午夜清道夫」

夜间渗透卡尔达什边境，与布雷克上尉、狙击手渡鸦组成三人小队，7 个阶段：夜视仪渗透（N 切换）→ 清除前哨站（可潜行：敌人有「警觉值」，发现需要时间，蹲伏与消音武器更难被发现，被察觉后整组敌人一起警戒）→ 穿越村庄 → 突入大院逐屋清理、击毙高价值目标「铁蝎」→ 按住 F 下载情报 → 坚守 90 秒抵挡三波增援 → 东门打开乘直升机撤离。

设有检查点（死亡后按空格原地重来）、三档难度、最佳通关时间记录。

### 多人对战（对战 AI）

- **模式**：团队死斗、占领（A/B/C 三据点）、自由混战
- **地图**：沙丘镇（沙漠白天）/ 寒霜炼厂（暴风雪）/ 霓虹街区（雨夜都市）/ 货柜场（黄昏港口）
- **AI**：三档难度，会寻路、找掩体、投雷、夺点，也使用连杀奖励
- **Perk**：3 栏位共 12 项（双倍时间、拾荒者、爆破专家、冷血、强硬路线、火力过载、幽灵、速愈、快手、振奋、静步、高度警觉）
- **连杀奖励**：侦察无人机、集束空袭（手动标记目标）、哨戒机枪、武装直升机、白磷弹，每次选 3 项
- **空中打击可以被打下来**：武装直升机有 8 段命中体（座舱 / 旋翼主轴 / 机身 / 尾梁 / 垂尾）与 600 点机体血量。子弹只造成 35% 伤害（打要害再 ×1.8，约两个弹匣放倒），RPG-7 直击要害一发即毁、直击非要害打掉八成血；血量低于七成开始冒烟。装甲表与 `takeDamage` 只有一份（`js/mp.js:HELI_ARMOR`），单机与联机权威端用的是同一个类
- **计分**：击杀奖章（爆头 / 远距离 / 双杀 / 三杀 / 首杀）、助攻、经验值与等级
- **联网对战**跑在真对局服务上（见《实时联机》）。模式规则与连杀奖励两端共用同一份实现（`js/match-rules.js` + `js/combat.js` 的 `clusterStrike`/`phosphorusSweep`），服务端是唯一裁决者；**集束空袭的选点两端是同一套**（准星落点环 + 左键确认 / 右键取消，`js/mp.js` 与 `js/net/client.mjs` 的 `updateTargeting` 同一形状），差别只在**谁扣槽**：单机本地扣，联机把落点发窄帧、由权威端验完半径再扣（请求被拒时那个槽不会白扣）—— 输入相同，裁决者不同。

### 武器与枪匠

- **12 把枪**：M4A1 / AK-47 / SCAR-H、MP5 / Vector、PKM、M870、SKS、L115A3、M1911 / .357 左轮、RPG-7
- **枪匠**：8 个配件栏位、每把最多装 5 个，属性正负影响实时对比显示；3D 模型可拖拽旋转缩放，7 种迷彩（含黄金）
- **配装**：5 套自定义，可改名，也可对局中途更换（下次部署生效）
- **装备**：致命 = 破片手雷（可烹饪）/ 粘性炸弹 / 燃烧瓶；战术 = 闪光弹 / 烟雾弹 / 兴奋剂

### 画面

PBR 材质 + 实时阴影 + ACES 色调映射，后处理含泛光、调色、FXAA；天气有沙尘 / 暴雪 / 降雨与动态天空；特殊效果为夜视仪、热成像瞄具，以及受伤、闪光致盲、白磷弹的屏幕效果。

## 实时联机

服务端权威：客户端只上报输入，模拟、命中、规则、结算全在 Node 侧跑，20Hz 下发定长快照，客户端做预测 + 回滚重放 + 对账。

**联网流程**（主菜单 → 联网对战，一条 WebSocket 从大厅走到对局，不换页不重连）：

1. **注册页（闸）** —— 要账号的服上未注册先到这一屏，办完身份自动前进；与大厅分屏（注册是前置条件，不是大厅的一部分）。
2. **大厅** —— 实时房间列表（服务端一变动就推，不轮询）+ 全服聊天；加入 / 快速加入（fill-first）/ 创建房间。房名是显示名，房号另有白名单 `[A-Za-z0-9_.-]`，中文房名由服务端另编一个。
3. **房间** —— 两队座位栏（含准备状态与空位）+ 房间聊天 + 准备 / 开始游戏。只有**房主**能开局，条件在服务端：至少 2 个在场者（Bot 算一个）且其余全部已准备；界面置灰与服务端放行问的是同一个函数。房主离开移交给下一个在线的人；地图/模式/时长/胜利目标/Bot/补人只有房主能改，开局后改不动。胜利目标与时长同一套规矩：候选值在 `js/data.js` 的 `MP_SCORES`（两端共读，服务端清洗，不认的退回 `js/match-rules.js` 的 `DEFAULT_SCORE_LIMIT` 按模式给的默认 —— tdm 50 杀 / ffa 25 杀 / dom 200 分），随 `createRoom`/`roomCfg` 的 `scoreLimit` 走 `beginLive` 的 cfg 进规则内核，并在 `welcome` 里下发。**三种模式都可联机（团队死斗 / 占领 / 自由混战）**：可玩性由 `js/data.js` 里 `MP_MODES` 的 `net` 标记决定（服务端判得出胜负的那些），`server/lobby.mjs` 按同一标记拒绝 —— 要加一格玩法，先给它在权威端补上胜负判定，再把 `net` 翻成 `true`。
   - **Bot 由房主手动加**（每队一个「+ Bot」，点 Bot 那一行即移除，难度三档全体一起改），**或者交给房间设置里的「补人」那一档**（默认关）：开着的时候这一间永远是满的 —— 补满到 16、有人离开或一局打完就补回来、真人进来时 Bot 让位（总数不变）、房主手动减掉一个就自动关掉补人（不然就是"点了减，名单纹丝不动"）。Bot 与真人**共用 16 个位置**，所以 `1 人 + 1 Bot` 就能开局 —— 屋里只有两个人时也能打一场像样的仗。它与连杀奖励那些实体一样是**权威实体**：跑在服务端、编进同一份 25 字节/实体的快照、进记分板、死了自己会回来（延迟与单机同一条式子）。名单在**等待态**才能改（补人也只在这个态生效），开局那一刻被读进 sim；之后再动就要往一个正在跑的世界里插人，而客户端的名册是在 `welcome` 里一次性给的。
4. **对局** —— 打完自动回房间，座位保留、准备状态清零，房主可接着开第二局。

**进对局需要账号**（`REQUIRE_ACCOUNT=1`，未完成注册前联网对战不开放）。这不是只把按钮置灰：没会话拿不到 `/api/rooms`（401），WebSocket 握手也是 401。主菜单入口不藏，只标 🔒。`REQUIRE_ACCOUNT=0` 的访客可玩服跳过注册页直接进大厅（本地调试与对战测试走这条）。要账号的原因不是防 DDoS，而是账号是"封人"的前提。

注册要邀请码（`JOIN_CODE`）；生产模式下不设它会被拒绝启动（见配置闸）。

也可以直接给 URL 多开：`?online=1&room=xxx&team=B`（建房可带 `&title=房间名`）。该直连协议形状未动，但**从大厅开出的是私人房**，手打房号挤不进去；直连路上没有房间，地图由该实例的 `MAP` 决定。URL 里的 `name=` **不再是身份** —— 呼号由服务端从会话取，join 帧那一格不会被看。

### 协议要点

- 下行快照定长：头 11 B + 每人 25 B。16 人 @20Hz 时**每客户端 65.8 kbps**（由 `node server/codec.mjs` 自测打印，改字段就会变，该自测在 `npm test` 里）。
- 上行输入 16 B/拍/人，攒一渲染帧一个包。其中 `view`（u16，最后 2 B）= **发出这一拍时我屏幕上渲染的是服务端的哪一拍**，延迟补偿需要的全部输入就是它；报拍号而不是"我延迟几拍"，因为后者要把 `INTERP_DELAY` 和本机帧时序折成一个数，于是两端各有一份会各自漂移的延迟模型。拍号每 65536 回绕，服务端按 `cur` 高位拼回绝对拍号。
- `streak`（最后 1 B）= 这一拍按了 3/4/5 中哪一个，没按 `0xff`。它必须是**按下沿**而非按住，这样上行每条最多一条请求，服务端不必再做边沿检测；服务端只在**真的消费到新输入的那一拍**处理它（饥饿空跑复用的旧输入里可能还留着上次请求）。
- 命中盒只有**一处定义**（`js/combat.js:hitTestPlayer`），服务端当下裁决 / 服务端回溯裁决 / Bot 裁决 / 客户端反馈（本机与远端）五处共用；回溯缓冲也只存命中盒依赖的那 4 个标量（Bot 的环存它自己的 `curEye()`，与裁决用的盒子同源）。
- 敌我键只有**一个形状**：团队模式 `'A'`/`'B'`，自由混战每人一支独立队 `'P'+cid`（Bot 用同一个分配器取号，`'P'+netId`，永不撞号）。快照那 1 字节的 team 表达不了序号 —— `'P'` 前缀统一占 `'P'` 通道（字节 2），**FFA 下快照字节不作敌我用**：名牌、own/foes 路由、"敌方"播报前缀、直升机归属一律以 roster / 事件里的**原始队键串**为准（附二十一）。Bot 在 FFA 下与真人一样重编独立队 —— 不重编它终生带着大厅发的 A/B，两营各抱一团、出生点各堆一翼。

### 延迟补偿

三跳各做一件事：① 客户端每拍上报 `view`；② `rewindTick` 过闸 —— 右端是不可伪造的 `lastSnapSent`（我确实发过这一拍），左端是 `LAG_MAX_TICKS = 60`（1 秒），四种情况一律拒绝（一份快照都没发过 / 报当下或将来 / 比已发的新 / 超上限）；③ 过闸后从 `PoseRing` 取那一拍的 `[x, y, z, eye]` 交给 `traceBullet` 的 `rewind` 回调。

**回溯集合里必须有人也有 Bot**（附二十）：真人环挂在 client 上，Bot 环挂在房间的 `botPose` 表里，同一把尺、同一个报值、同一道窗。少一半的症状是"打真人正常、打移动 Bot 永远偏"——Bot 在客户端屏幕上滞后 ~150ms，横向一走就出盒。

出窗的报值一律**拒绝并退回按当下判**，不夹到窗沿：夹了能换成"错得少一点的补偿"，但那是把"我看到的其实是一秒前"抹成一个假的深度。客户端帧时序导致的那约 0.5 秒残差会记在 `/healthz` 的 `lag.stale` 上，不是静默的。客户端的插值回退 `INTERP_DELAY` 不再写死 100ms：按快照到达间隔与抖动的 EMA 收放（55–120ms），`renderTick` 与插值读同一个活绑定，报值与画面永远同一拍（附二十）。

### 预测与回滚

`js/net/predict.mjs` 在收到快照时回滚重放，并把纠正**写回日记本基态**（否则下一次回滚落回同批拍会把上次的纠正整个作废，同一笔位移反复重犯）。服务端 `step()` 每步二选一（有货消费 / 无货拿手里那份空跑），所以两包之间的 `dTick` 步里空跑可能落在消费**之前**，而随包的 `rep` 只报末尾连拍；客户端按 `lead → dAck 条真输入 → rep 空跑` 的实际顺序重演，恒等式 `applySteps == dTick` 由判据比过。

一条跨引擎事实：**Node 与 Chrome 的 sim 不可能逐位一致，这是规范允许的，不是 bug**（`sin/cos/tan/atan2/asin/acos/pow/exp/log/cbrt` 只要求"实现近似"，本机实测 11 个函数位模式不同；`sqrt/hypot/乘加` 要求精确舍入，逐位相同）。只有服务端跑权威 sim，浏览器是每 20Hz 被校正的客户端，所以它只表现为"预测误差的下限"，不会让两边状态永久错开。`server/xenv.mjs` 的判据按引擎指纹自校准成两档（指纹全同 ⇒ 逐位全等；指纹有异 ⇒ 改判四条结构性性质）。

### 账号与安全的设计约束

- **令牌放 HttpOnly cookie，不放 Bearer + 前端存储**（游戏里呼号会进记分板和 HTML，一次 XSS 就能读走前端令牌）。CSRF 靠**结构性**三道：`SameSite=Lax` + 只收 `content-type: application/json`（非简单请求必走预检，而不给任何 CORS 头）+ 方法白名单。附带好处：WebSocket 握手自动带 cookie ⇒ 服务端在 upgrade 那一刻就钉死身份。
- **呼号只有一个来源，两种情况，判据只有一处**（`server/net-server.mjs` 的 `joinName`）：要账号的服来自会话；访客服没有会话可依，自报呼号是唯一来源但仍要过同一个白名单。非法自报呼号**直接拒绝并说明规则**，不静默改成"访客"（"被改掉了"和"没生效"是同一副长相）；没带名字按"访客"进。访客服里按账号算的建房配额是空转的（已知被放弃的一项，有判据记录）。
- **密码用异步 `crypto.scrypt`（N=2^15，每次 32 MiB），不能是 `scryptSync`**：同步版会把事件循环停住约 100 ms，而同进程跑着 60 拍/秒的权威 sim —— 一次登录高峰就把所有房间停住，且不崩、不错、功能全对。令牌用 sha256 快哈希（256 位均匀随机，没有弱口令空间可枚举）。哈希吃 libuv 线程池，所以另设并发闸门：宁可当场拒"服务器忙"，不排队。
- **"这个呼号存不存在"不许泄露**：`bad_credentials` 一句话覆盖"没这个人"与"密码错"，且用户不存在时也跑一次真哈希（否则两条路径耗时差就是账号枚举器）。邀请码比较用 `timingSafeEqual`，不许 `===`。
- **忘了密码只有一条出路：注册时抄下来的恢复码**（`server/accounts.mjs`）。注册与每次重设各一次性发 5 张 `XXXX-XXXX-XXXX`（12 位 × 32 字母表 = 60 位；字母表去掉 `I L O U`，抄错的 `O→0`、`I/L→1`、大小写与空格由 `normalizeRecoveryCode` 吃掉 —— **规范化必须做在哈希输入上**，否则码抄得走形就等于作废）。库里只留哈希，落在 meta 抽屉里（`setMeta` 是直写，不需要动 `users` 表结构、不需要一次 schema 迁移）。用掉任意一张 ⇒ **整套作废并换发一叠新的**（不然"用掉一张"只是让可用的秘密变多）。重设成功 = 一次登录（当场发会话 cookie）+ **作废该账号全部旧会话** —— 少了后半句，捡到码的人改完密码也赶不走原主。这条路与登录**共用同一张限流表、同一句 `bad_recovery`**（"没这个人 / 没码 / 码抄错"三者同貌，否则找回接口就是个比登录更好用的账号枚举器），而且不管码命中第几张都跑满 5 次真哈希（提前 `break` 会把"第几张"漏成耗时差）。服主侧只有补发这一个口子：`node server/recover.mjs`（**只能发码，不能设密码**），每次补发在审计表里留一行 `recover:cli_issued`。
- **存档权威在服务端，且写盘不在 tick 里**：`endMatch` 只把名单挂队列（O(1) 内存记账），1 秒一轮的 `resultDrain` 在循环外写档。存储是 `node:sqlite`（零依赖），写穿 + 攒批刷盘（每 250 ms 一批，单批 ≤ 200 条），代价是进程被杀最多丢 250 ms 写入。**不要**设计"客户端上报本局得分"那种接口。
- **账号状态按需拉，不在页面启动时问**（`js/main.js` 的 `accountSync`）：`?online=1` 那条直接进对局、根本不画菜单的路上，页面加载里挤进的两次请求正好落在客户端第 0 拍与权威端 `addClient` 对齐那一瞬，实测会把稳态预测偏差顶高一档。
- 限流按 IP 而 IP 可伪装；`TRUST_PROXY` 是反代**层数**不是布尔，认了没有代理的 `X-Forwarded-For` 等于把限流 key 交给攻击者自己填。

| `ROOMS_PER_USER` | `2` | 每账号同时拥有的房间数 |

模板在仓库根 **`.env.example`**（含"设错会怎样"）。⚠ 它**不是自动读取的配置**：服务端零依赖、没有 dotenv，要用 `docker run --env-file .env`、compose 的 `env_file`，或 `set -a; . ./.env; set +a` —— "改了 `.env` 却没生效"和"压根没配"在日志里长得一样。

**生产模式的配置闸**：上面两项"必须显式设"的不设就**拒绝启动**（打印出路后退出码 1）。起因是一个只在部署时发作的静默失效：`JOIN_CODE` 不设时取源码里那个**公开的**默认值，而上一版日志只看真值、于是打印"已设"；`ACCOUNTS_DB` 不设 = 内存库，而默认要求登录 ⇒ 进程一重启所有人的账号一起消失，且这件事只在重启后才看得出来。判据是停住而不是警告（警告在 `docker logs` 里活不过三秒）。**显式的空值是允许的** —— 那是"我知道我在要什么"；开发模式两条都不卡，但日志必须写明"在用源码里的默认值"。⚠ 只有 `ALLOW_ORIGIN` 是例外、也只能是例外：确实存在**不需要**来源检查的部署，所以它不掐服务，代价是它必须喊得比这两条响（生产模式下多行 + 写清后果 + `启动完成` 哨兵收尾，判据见 `test/hardening.mjs` 的 H7/H8，理由见下面《容器与下线》与 `docs/net-vs-local-gaps.md` 附十三）。

### 带宽与容量

容量是压出来的，不是算出来的：`npm run soak`（默认阶梯 1 / 2 / 4 / 8 间 × 16 人 = 16 → 128 人，位置参数只认纯数字那一档，`node server/soak.mjs 16` 即 256 人），也能压远处实例 `node server/soak.mjs --url=https://your.domain`（`--url` 要的是 **http(s) 基址**：它据此 fetch `/healthz`，并把 `^http` 换成 `ws` 得到对局地址；要账号的服带 `--cookie=mf_sid=...`）。两个必踩的坑：生产通常设了 `ALLOW_ORIGIN`，而 `ws` 库不发 Origin 头 ⇒ 全部 403（soak 对外部目标默认带"目标自己"这个来源，跨源用 `--origin=`）；`CONNS_PER_IP` 默认 6，本机压测所有连接同一 IP，第 7 个就被拒（本机读数用 `CONNS_PER_IP=256` 跑出）。

读数以**服务端自报**为准（假客户端跑在压测进程里，从对面数帧率分不清是服务器慢还是压测机慢）。本机（Windows，单进程）实测：

| 人数 | 间数 | 每间 hz | 每拍耗时 | 落后墙钟 | 下行/人 | 峰值堆 |
| --- | --- | --- | --- | --- | --- | --- |
| 16 | 1 | 60.1 | 0.125 ms | 0 ms | 20.0 Hz | 15.7 MB |
| 64 | 4 | 59.9 | 0.083 ms | 0 ms | 20.1 Hz | 26.5 MB |
| 128 | 8 | 59.3 | 0.064 ms | 0 ms | 20.0 Hz | 25.0 MB |
| 256 | 16 | 59.1 | 0.060 ms | 0 ms | 20.1 Hz | 36.5 MB |

256 人这一档仍未到模拟瓶颈（每拍 0.06 ms，预算 16.7 ms）；压完房间回收后堆回落到 20 MB。

### 反向代理

TLS 交给 nginx / Caddy，`wss` 必须显式转发 Upgrade 头，否则浏览器握手直接失败：

```nginx
location / {
  proxy_pass http://127.0.0.1:8090;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
  proxy_read_timeout 120s;          # WS 空闲期，别用默认 60s 掐断
}
```

`ALLOW_ORIGIN=https://your.domain` 之后别的站点就借不走你的对局服务（WebSocket 不受 CORS 约束，不检查来源等于对所有网站开放）。

### 容器与下线

配置按 `.env.example` 抄一份（改掉 `JOIN_CODE` 与域名），用 `--env-file` 在运行时喂进去 —— **不要把 `.env` 打进镜像**（`.dockerignore` 已挡）：

```bash
docker build -t mw-room .
docker run -d -p 8090:8090 --env-file .env -v mw-accounts:/data mw-room
```

**账号库要挂出来**，否则容器一重建所有人就登不上（`.env.example` 里 `ACCOUNTS_DB=/data/accounts.db` 指容器内路径）。

- 健康检查 `GET /healthz` → `{ok, rooms, clients, tickHz, uptime, draining, heapMB, per[]}`；`per[]` 逐间报 `hz / stepMs / behindMs / fails`；另有 `lag{shots, ok, noView, stale, poseMiss, depth[], botRewound, botPoseMiss}`（延迟补偿计数——bot 两格是 Bot 那一半的观测，没有它们时"Bot 全部按当下裁决"在 shots/ok 上完全看不出）与 `streak{calls, accepted, rejected, byId}`、`worldFlags`、`gate{}`、`auth.store`（`MemoryStore` vs `SqliteStore`）、`lobby{}`。这些计数存在的理由是一样的：这类失效在玩家侧只表现为"打不中""按了没反应"，运维得能在服务端先看见。Dockerfile 已挂 HEALTHCHECK。
- 下线：收到 `SIGTERM` 先置 `draining`（LB 可据此摘实例），给在册连接发一条带原因的 `note` 并以 `1001` 关闭，停房间循环，在 `SHUTDOWN_GRACE_MS` 内退净。
- ⚠ 上面两条 docker 指令在本机**没跑过**（开发机没装 docker）。不需要 docker 的那一半已经量了（`test/image.mjs`，在 `npm test` 里）：每条 `COPY` 的源都在仓库里、`CMD` 指着真文件、镜像默认 `NODE_ENV=production`、非 root、运行时导入闭包（从 `server/net-server.mjs` 递归推的 32 个文件）与 `PUBLIC` 白名单一条都没被 `.dockerignore` 挡住、闭包里没有一处 import playwright，而且 Dockerfile 里那句 HEALTHCHECK 的 payload 会被抠出来**对一台真服跑**（退出码 0）**再对一个空端口跑**（退出码必须 1）。剩下没验的就是这四条：真的 `docker build`、真的 `docker run`、镜像层体积、以及 `SIGTERM` 那段在 **Windows 上没被测过**（libuv 的 `child.kill()` 是直接 TerminateProcess，信号送不进子进程），Linux 上由 `server/deploy-probe.mjs` 验收。

### 真机部署

按 **`docs/deploy-checklist.md`** 走六节：先 `npm test` → 起一台生产模式实例（配置闸"红了怎么看"的对照表）→ 远程体检 → 远程压测 → 容器三步（那三条命令本机没跑过；配方本身由 `test/image.mjs` 在 `npm test` 里静态量过）→ 上线后要盯的三个数。

两个量具都是**从外面看**的（起进程 ≠ 验服务）：

- `node server/remote-probe.mjs --url=http://ip:8090`：只读体检（`/healthz` 各字段、静态白名单、来源检查、限流），要账号的服上再加 `--invite=<邀请码> --register` 才做会写库的那几笔（可配 `--name=`）。其中生产模式的来源检查是机器可查判据：`gate.originCheck` 自报要与"陌生来源被 403"的实测一致。
- `node server/soak.mjs --url=...`：远程容量阶梯，读数仍以服务端自报为准。
- `node server/recover.mjs --db=/data/accounts.db --name=某呼号`：忘到"恢复码也没了"时的最后一条路 —— 给这个呼号**补发一叠 5 张新恢复码**（补发即作废旧的那一叠），念给本人。它**不能设密码、不能改呼号**，也不打印任何旧码；谁在什么时候给谁补发过，审计里有 `recover:cli_issued`（`node server/audit-dump.mjs --db=/data/accounts.db --ev=recover:cli_issued`）。

### 验收

```bash
npm test              # 主体档：gate + docs-guard + rollback + reconcile-chain + world-equiv + net-journal + codec + lagcomp + mp-rules + accounts + progress + hardening + service-guards + room-flow + room-bots + room-dir + image + net-probe + deploy-probe + xenv + fps + viewmodel + gunvisual + net-feel + net-audit + heli-armor + optic + state-leak
npm run test:browser  # 对打 / 掉线 / 同源双标签页三档：net-play + net-drop + tab-session
npm run test:all      # 上面两档全跑
```

改这套代码之前先看它绿不绿。每份测试都带**反证臂**（"该有的东西必须还在"）—— 只写"坏的要红"那一半的话，把功能整个删掉也能全绿。

**比两个客户端的位置，只能比同一个服务端 tick。** "各自最后收到的那一包"不是同一拍：4.7 m/s 下错一包就是 0.12 m 的假差，于是这类判据随"谁先被调度到"又绿又红（`server/net-probe.mjs` 与 `test/net-play.mjs` 都在这上面红过，单独跑却都是绿的）。两份现在都**同时取样、只认共同的那一拍**，容差跟着收到 `1e-6`（同一拍的那份下行是同一批字节，逐位相同才是它该有的样子）。同理，凡是拿"我自己这一步"当尺子的判据，都得把"这一步真的在动"单列成一条判别臂 —— 站着不动时那把尺子会缩到量化噪声上去。换掉的旧尺子、以及新尺子那两条臂，由 `test/docs-guard.mjs` 的 D′ 段钉住不许换回去（记录见 `docs/net-vs-local-gaps.md` 附九）。第 9 轮又踩到同一类一次：`test/hardening.mjs` 那条"关掉一条连接之后名额还回来了"原本是 `await sleep(300)` 再重连 —— 拿**客户端的钟**去等服务端把 `close` 事件跑完，机器被拖热时 300 ms 不够，当场红成"配额没还回来"（`test:all` 最后一段红过一次，紧接着同一份代码单跑两次 111/111）。尺子同样换成了**服务端自报的数**（`/healthz` 的 `clients`，它和 `connsByIp` 的减一写在同一个 `ws.on('close')` 里），轮询到"在线数真的降了"再重连。第 10 轮把"尺子会缩到噪声"这条原则用到了空跑窗那把尺子自己身上：静止格给 `2×POS_STEP` 的下限、走动格仍按自己的步长量（`js/net/idle-ruler.mjs` + `test/net-feel.mjs` AA 段，旧尺子由 D′ 立碑不许回潮），见 `docs/net-vs-local-gaps.md` 附十四/附十五那条账。

**要真浏览器**：`xenv` / `fps` / `viewmodel` / `gunvisual` / `optic` / `state-leak` / `net-play` / `net-drop` / `tab-session` —— 这份名单是**从源码推的**（谁 `import { chromium } from 'playwright'` 就是谁），守卫拿它逐份去对，漏写和多写都红。这 9 份的 `launch()` 都按同一顺序试三档：**系统 Chrome** → **Playwright 自带的那一份**（不带 `channel` / `executablePath`，所以 `npx playwright install chromium` 装的就是它）→ 本仓库开发机上实际存在的那份绝对路径。中间那一档是"别人的机器能不能跑起来"的全部依据：改动前 8 份只有"Chrome + 那台开发机的绝对路径"两档，于是本仓库那句安装提示在没装 Chrome 的机器上是句空话 —— 现在文档守卫的 G 段逐份核它（少一档就红）。其余判据都在进程内跑完，不碰浏览器。

- `server/gate.mjs` / `codec.mjs`：协议字段与包长自测（包长一变就打印新值）

## 已知缺口

联机与本地的手感差距另有一份只读走查清单：`docs/net-vs-local-gaps.md`（45 条 + 每条的判据守卫 + 收口记录）。下面是部署与账号层面的缺口。

1. **战役的经验值不进账号**（有意）：单机模拟客户端能自己算，服务端无法验证，报上去等于给了个免验证的加经验入口 —— 所以账号 xp 只来自多人对局。
   这一条以前**不只是"不进账号"，它还会被账号抹掉**：本地经验与服务端经验挤在同一个 `profile.xp` 上，于是任何一次账号同步（登录、进主菜单按需问一次 `/api/me`）都把战役那一笔盖成服务端那个数 —— 不报错、不崩，只是打完一整场战役回主菜单，经验条原封不动。现在两半分开存（`js/progress.mjs`：`xp` = 账号那份、`xpLocal` = 本地那份；战役 / 单机 / 访客联机走 `addLocalXp`，账号同步走 `applyAccountXp`），档案卡上分开写出来（`等级 N · 账号 X XP · 本地 Y XP（本地不计入账号）`），等级按两半之和算；联机记分板与房间座位栏那一列读的仍然是服务端自报的账号 xp（同一张表里不能有两个来源）。判据 `test/progress.mjs`（21 条）。
2. ~~账号自己找不回来（密码忘了就进不去，只能等人改库）~~ 已收口（2026-09-30 · 一次性恢复码）：注册与每次重设各发 5 张 `XXXX-XXXX-XXXX`，库里只留哈希（meta 抽屉，不动 `users` 表结构），用掉任意一张即整叠轮换；重设成功 = 登录 + **作废该账号全部旧会话**；与登录共用限流表和同一句 `bad_recovery`（没这个人 / 没码 / 码抄错三者同貌）。服主侧只有补发这一个口子（`server/recover.mjs`，它不能设密码），每次补发在审计里留 `recover:cli_issued`。判据分三层：`test/accounts.mjs` 的 K 段（34 条，含生产 scrypt 下的计时臂）、`test/hardening.mjs` 的 J 段（18 条，真 HTTP + 真库文件 + 真 CLI）、`test/net-drop.mjs` 的 I 段（真浏览器里那块横幅）。设计理由、"能不能红"的三次实测与仍未收的那半（没接邮箱/短信，码丢了只能找服主）见 `docs/net-vs-local-gaps.md` 附十二。
