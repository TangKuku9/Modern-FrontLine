# 现代战线 MODERN FRONTLINE

一款在浏览器里运行的现代军事题材第一人称射击游戏（原创致敬作品），用 Three.js 写成，**没有用到任何外部美术或音频素材**：所有纹理（包括法线和粗糙度贴图）、模型和音效都由程序实时生成。

## 开发背景

本游戏全程仅通过 **Claude Opus 5.5** 的**一轮对话**生成完成。

- 实机游玩视频：[B 站 BV1poaP6YEKy](https://www.bilibili.com/video/BV1poaP6YEKy)

## 运行方法

游戏使用 ES Module，必须通过本地 HTTP 服务器打开，直接双击 html 文件打不开：

```bash
cd mw
python3 -m http.server 8080
# 然后在浏览器打开 http://localhost:8080
```

推荐使用最新版 Chrome 或 Edge，并开启独立显卡。如果帧数偏低，可以在「设置」里调低画面质量。

## 内容

### 战役：行动代号「午夜清道夫」
夜间渗透卡尔达什边境，和布雷克上尉、狙击手渡鸦组成三人小队，共 7 个阶段：
1. 夜视仪渗透（按 N 切换夜视仪）
2. 清除前哨站。可以选择潜行：敌人有「警觉值」，发现你需要一段时间；蹲伏和使用消音武器都更难被发现，被察觉后整组敌人会一起警戒
3. 穿越村庄
4. 突入大院，逐屋清理，击毙高价值目标「铁蝎」
5. 按住 F 下载情报
6. 坚守 90 秒，抵挡三波敌方增援（包括皮卡运兵）
7. 东门打开，乘直升机撤离

其他：设有检查点，死亡后按空格从检查点重来；可选三档难度，并记录最佳通关时间。

### 多人对战（对战 AI）
- **模式**：团队死斗、占领（A/B/C 三个据点）、自由混战
- **地图**：
  - 沙丘镇：沙漠，白天
  - 寒霜炼厂：暴风雪
  - 霓虹街区：雨夜都市
  - 货柜场：黄昏港口
- **AI**：分三档难度，会寻路、找掩体、投雷、夺点，也会使用连杀奖励
- **Perk**：3 个栏位共 12 项，包括双倍时间、拾荒者、爆破专家、冷血、强硬路线、火力过载、幽灵、速愈、快手、振奋、静步、高度警觉
- **连杀奖励**：侦察无人机、集束空袭（手动标记目标）、哨戒机枪、武装直升机、白磷弹；每次从中选 3 项
- **计分**：有击杀奖章（爆头、远距离、双杀、三杀、首杀）、助攻，以及经验值和等级系统
- **另一种"多人"**：主菜单里的「联网对战」跑在真对局服务上（见下面《实时联机与云端部署》）。**模式规则与连杀奖励现在两端共用同一份实现**（`js/match-rules.js` + `js/combat.js:clusterStrike/phosphorusSweep`），服务端是唯一的裁决者；唯一按模式不同的地方是集束空袭的落点怎么定（单机是玩家在地图上点一下，联机省掉这次点击、改用呼叫者视线前方 22 m）—— 那是输入不同，不是规则不同（见下面第 4 条）。

## 实时联机与云端部署

### 本机先跑起来

```bash
npm install                 # 只有两个运行时依赖：ws、three
npm start                   # http://127.0.0.1:8090/  同一个端口发静态资源 + 跑 WebSocket
```

主菜单 → **联网对战** → 注册或登录 → 选阵营、（可选）房间号 → 加入对局。不带房间号时由服务端
把人往人最少的那间塞。想开两窗对打：第二窗选别的阵营，或两窗填同一个房间号。

**进对局需要账号。** 注册要邀请码（`JOIN_CODE`；本机不设时用源码里的默认值，日志会写明这一点 ——
**生产模式下不设它会被拒绝启动**，见下面的配置闸）。
这样做不是为了防 DDoS（那要放到云厂商前面），而是因为账号是"封人"的前提：
没有身份，服务端就只能看着有人在自瞄而无处记录。

也可以直接给 URL（多开的快捷办法，效果与大厅里点一样）：`http://127.0.0.1:8090/index.html?online=1&room=xxx&team=B`。
URL 里的 `name=` **不再是身份** —— 呼号由服务端从会话里取，join 帧里那一格不会被看（见下面第 1 条）。
地图与模式由服务端的环境变量决定（见下表），大厅不假装能选它。

### 环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `PORT` | `8090` | 监听端口（也支持 `node server/net-server.mjs 8090`） |
| `HOST` | `0.0.0.0` | 绑定地址；只走本机反代时可收 `127.0.0.1` |
| `NODE_ENV` | — | `production` 才启用静态资源白名单（等价开关：`--prod`） |
| `MAP` / `SEED` | `yard` / `20260925` | 该实例跑的地图与玩法随机流种子 |
| `MAX_ROOMS` | `32` | 每进程房间数上限（一间 = 一份完整 sim） |
| `MAX_CLIENTS` | `128` | 每进程真人连接上限 |
| `MAX_PAYLOAD` | `65536` | 单个入站帧字节上限（正常一帧 ≤ 16×60 = 960 B） |
| `ALLOW_ORIGIN` | 空=不检查 | 逗号分隔的允许来源，**生产务必设** |
| `ROOM_IDLE_MS` | `60000` | 空房间多久回收 |
| `STATIC_MAX_AGE` | `86400` | 非 html 静态资源的 max-age |
| `SHUTDOWN_GRACE_MS` | `4000` | 收到 SIGTERM 后留给收尾的时间 |
| `JOIN_CODE` | 源码里的 `mf2026` | 注册邀请码；**设成空串 = 开放注册**（公开运营时才这么配）。**生产模式必须显式设**（含显式设空） |
| `ACCOUNTS_DB` | 空 | 账号库路径。**留空 = 只存内存，重启就丢**；设成路径走 SQLite（`node:sqlite`，零依赖）。**生产模式下 `REQUIRE_ACCOUNT=1` 时必须显式设** |
| `COOKIE_SECURE` | 跟随 `NODE_ENV` | 给会话 cookie 加 `Secure`。**明文 HTTP 部署必须设 `0`** —— 加了浏览器会静默丢掉它 |
| `TRUST_PROXY` | `0` | 反向代理**层数**（不是布尔）。0 = 完全忽略 `X-Forwarded-For`；认了它而背后其实没有代理，等于把限流交给攻击者自己填 |
| `REQUIRE_ACCOUNT` | `1` | 进对局要不要登录。设 `0` 放开成访客可玩（只在本地调试用，见下） |
| `REG_PER_HOUR` | `8` | 每 IP 每小时注册次数上限 |
| `LOGIN_PER_5MIN` | `12` | 每 IP / 每呼号每 5 分钟登录尝试上限（失败还有指数退避） |
| `CONNS_PER_IP` | `6` | 每 IP 同时 WebSocket 连接上限 |
| `WS_MSG_PER_SEC` | `240` | 每连接每秒消息上限。正常客户端 60 帧/秒，超了**拆连接** |
| `ROOMS_PER_USER` | `2` | 每个账号能同时拥有的房间数 |

一份可以照着抄的模板在仓库根的 **`.env.example`**（含"设错会怎样"的说明）。
⚠ 它不是自动读取的配置：服务端零依赖、没有 dotenv，要用 `docker run --env-file .env`、
compose 的 `env_file`，或者手动 `set -a; . ./.env; set +a` —— **"我改了 `.env` 却没生效"
和"我压根没配"在日志里长得一样**，所以模板第一行就写了这件事。

#### 生产模式的配置闸（"忘了设"不许长得和"设好了"一样）

生产模式（`NODE_ENV=production` 或 `--prod`）下，上面标了"必须显式设"的两项不设就**拒绝启动**
（打印两条出路后以退出码 1 退出）。起因是一个只有部署时才发作的静默失效：

- `JOIN_CODE` 不设时取源码里的默认值，而它是**公开的**（就在仓库里）；上一版的启动日志只判断真值，
  于是打印 **"邀请码 已设"** —— 忘了设环境变量的操作员看到的是"已配好"，而门是开着的。
- `ACCOUNTS_DB` 不设 = 内存库，而默认要求登录 ⇒ 进程一重启所有人的账号一起消失。
  这件事**只在重启之后才看得出来**，那时已经有真玩家了。

所以判据不是"打个警告接着跑"（警告在 `docker logs` 里活不过三秒），而是停住。
显式的空值是**允许**的 —— 那是"我知道我在要什么"：`JOIN_CODE=` 表示我就是要开放注册，
`REQUIRE_ACCOUNT=0` 表示这是个不存档案的访客服。开发模式（本机 `npm start`）两条都不卡，
  但日志必须写明"在用源码里的默认值"/"未设 `ACCOUNTS_DB`"（`test/hardening.mjs` 的 H 段，
  每条"拒绝"都配了一条"该放行的必须放行"的反证臂 —— 只写前一半的话，
  把 prod 写成无条件退出也能全绿，那是把服务整个焊死）。

### 带宽与 CPU

- 下行快照定长：头 11 B + 每人 25 B。16 人 @20Hz 时**每个客户端 65.8 kbps**（`node server/codec.mjs` 自己印出来，改字段会变；这条自测现在也在 `npm test` 里 —— 加宽输入包那次才发现它一直只被手动跑）。
- 上行输入 16 B/拍/人，攒一渲染帧一个包发。最后那 2 B 是 `view`：**发出这一拍时我屏幕上渲染的是服务端的哪一拍**
  （低 16 位）。延迟补偿要的全部输入就是它 —— 服务端据此把别人拨回开枪者当时看到的位置（见下面第 2 条）。
  为什么不发 u8 的"我延迟多少拍"：那个量得由客户端把 `INTERP_DELAY` 和自己的帧时序折成一个数，于是两端
  各有一份会各自漂移的"延迟模型"，症状是"高延迟下总是差半步"；直接报拍号不需要任何模型，而且服务端能用
  "我确实发过这一拍"把它卡死上限。@60Hz 也就多 0.96 kbps。
- 最后 1 B 是 `streak`：**这一拍按了 3/4/5 里的哪一个**（0/1/2），没按是 `0xff`。
  它必须是"按下沿"而不是"按住"—— `Digit3` 只进 `pressed` 表、只在一拍为真，所以上行的每一条里最多有一条
  带请求，服务端因此不需要再做边沿检测。这一位以前**只存在于客户端**（`js/main.js:snapshotInput` 填了它，
  但 codec 只搬 `keys/buttons`），于是联机下按 3 呼叫连杀奖励是真的什么都不做：不报错、不崩，只是没反应。
  服务端在**真的消费到一条新输入的那一拍**才处理它（饥饿时空跑复用的同一份输入里可能还留着上一次的请求，
  按"每拍看一次"写会让一个槽被连点）。@60Hz 再多 0.48 kbps。
- 容量是压出来的，不是算出来的：`npm run soak`（阶梯 16 → 128 人，最后一档可 `node server/soak.mjs 16` 压到 256 人）。
  读数以**服务端自报**为准（`/healthz` 逐间给 hz / 每拍耗时 / 落后墙钟毫秒），因为假客户端跑在压测进程里，
  从对面数出来的帧率分不清是服务器慢还是压测机自己慢。

  本机（Windows，单进程）实测：

  | 人数 | 间数 | 每间 hz | 每拍耗时 | 落后墙钟 | 下行/人 | 峰值堆 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 16 | 1 | 60.1 | 0.125 ms | 0 ms | 20.0 Hz | 15.7 MB |
  | 64 | 4 | 59.9 | 0.083 ms | 0 ms | 20.1 Hz | 26.5 MB |
  | 128 | 8 | 59.3 | 0.064 ms | 0 ms | 20.0 Hz | 25.0 MB |
  | 256 | 16 | 59.1 | 0.060 ms | 0 ms | 20.1 Hz | 36.5 MB |

  256 人这一档**仍然没到模拟的瓶颈**（每拍 0.06 ms，预算 16.7 ms），也就是说再往上先到瓶颈的更可能是
  网络写出与压测进程自己，而不是这份 sim。压完房间被回收后堆回落到 20 MB，长跑不会只涨不落。


### 反向代理

TLS 交给 nginx/Caddy，`wss` 需要显式转发 Upgrade 头，否则浏览器握手会直接失败：

```nginx
location / {
  proxy_pass http://127.0.0.1:8090;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
  proxy_read_timeout 120s;          # WS 空闲期，别用默认 60s 把连接掐掉
}
```

设了 `ALLOW_ORIGIN=https://your.domain` 之后，别的站点就借不走你的对局服务（WebSocket 不受 CORS 约束，不检查来源等于对所有网站开放）。

### 容器与下线

```bash
docker build -t mw-room .
```

配置按 `.env.example` 抄一份（`cp .env.example .env` 然后改掉 `JOIN_CODE` 与域名），
用 `--env-file` 在运行时喂进去 —— **不要把 `.env` 打进镜像**（`.dockerignore` 里已经挡了）：

```bash
docker run -d -p 8090:8090 --env-file .env -v mw-accounts:/data mw-room
```

**账号库要挂出来，否则容器一重建所有人就登不上了**（`-v mw-accounts:/data` 那句就是干这个的；
`.env.example` 里 `ACCOUNTS_DB=/data/accounts.db` 指的是容器内的路径）。

⚠ 不设 `JOIN_CODE` / `ACCOUNTS_DB` 的话进程会直接**拒绝启动**（见上面《生产模式的配置闸》）。
不设 `ACCOUNTS_DB` 时走内存存储这件事，在启动日志和 `/healthz` 的 `auth.store` 上都会写出来
（`MemoryStore` vs `SqliteStore`）—— 但它只在**你已经决定不要档案**（显式 `REQUIRE_ACCOUNT=0`）
的时候才是可接受的，所以那一步得你自己写出来。

- 健康检查：`GET /healthz` → `{ok, rooms, clients, tickHz, uptime, draining, heapMB, per[]}`；`per[]` 逐间报 `hz / stepMs / behindMs / fails`，扩容时看的是"哪一间先吃紧"，`fails` 在"一个客户端的坏数据打死一屋子人"之前就会先动。另有 `lag{shots, ok, noView, stale, poseMiss, depth[]}`：延迟补偿的四项计数，**"这个玩家永远没有补偿"在玩家侧只表现为打不中**，运维得能在这里先看见（定义见 `server/room.mjs` 的 `this.lag`）。`streak{calls, accepted, rejected, byId}` 与 `worldFlags` 同理，管的是**联机规则**那一侧：`calls=0` 意味着按 3 这件事根本没走到服务端（客户端旧版本，或者那一位没接通），而"按了没反应"在玩家侧和"这一项没实现"长得一模一样。Dockerfile 里已挂 HEALTHCHECK。
- 下线：收到 `SIGTERM` 后先置 `draining`（`/healthz` 里能读到，LB 可据此摘实例），给在册连接发一条带原因的 `note` 并以 `1001` 关闭，停掉房间循环，在 `SHUTDOWN_GRACE_MS` 内退净。
- ⚠ **上面这两条 docker 指令在这台开发机上没有构建验证过**：本机没装 docker。已验的是 `CMD`/`HEALTHCHECK` 依赖的那两条运行时事实（`node server/net-server.mjs` 的启动与 `/healthz` 读数、`SIGTERM` 走的是同一份 `shutdown()`），镜像本身要在有 docker 的机器上 `docker build` 一次才算数。
  ⚠ 这一段在 Windows 上**没被测过**：libuv 的 `child.kill()` 是直接 TerminateProcess，信号送不进子进程。Linux 上由 `server/deploy-probe.mjs` 的三条断言验收。

  "延迟越大越打不中"（报表上只是一串 miss）。
  **客户端那一半（报哪个拍号）单独量了 14 项**，因为它错了不报错：服务端会把出窗的报值一律拒掉 ⇒
  这个玩家永远没有补偿，不崩、不报错，只是打不中。主判据写成**恒等式**"报的就是现在 − `INTERP_DELAY`
  那一刻的服务端拍号"而不是区间（区间会让"深度从 6 拍漂到 3 拍"这种系统性变浅蒙混过关，而那正是
  `INTERP_DELAY` 被改小的形状）；它的反证臂是同一个函数在"目标时刻晚于最新一包"时报的**就是**最新那一拍

  并用跨过 65536 的一格证明"截断成 u16 再被服务端拼回来"回到同一个绝对拍号（这条链每 18 分钟走一次，
  接错线的症状是"服务开机 18 分钟之后所有人都打不中"）。最后一条是把已知行为钉成读数：消息攒着一起处理
  （主线程卡过一帧）时报值会落到最旧那一格、比窗还旧、**被拒**，等价于报 0（代价上限就是"这一小段没有补偿"），

- `test/mp-rules.mjs` 72 项：**联机规则**（连杀奖励 / 按拍排程 / 群体警戒 / 记分 / 隔离）的机制证明。
  它走**进程内**房间 + 手动 `step()`，因为这一项要量的是"第几拍生效"，而网络与定时器会把拍数搅糊 ——
  于是"呼叫集束空袭之后第 84 拍出现第一颗弹、第 137 拍九颗投完"是一条**确定性判据**，不是"等 1.4 秒看看有没有"。

  A 段先把量具自己量一遍（槽位簿记、按拍排程、分值），因为后面每一条都建立在"这本账是对的"之上，
  而一块错的量具会让后面每一条都变成恒真绿灯。B 段是全链路：击杀 → 充能 → 就绪 → 呼叫 → UAV 上线 →
  快照标志位亮，每一步都配反证臂；其中三条最有牙齿的是 **"就绪 ≠ 生效"**（3 杀只让槽位就绪，`worldFlags` 仍是 0）、

  （`js/ai.js` 的调用被 `game.alertGroup &&` 挡住，缺了实现在两边都不报错，只是"整组敌人不会一起警戒"），

  且跑 120 拍之后玩家存档里的经验值一个数都没动（权威端一旦能写档，就是"服务端可以被玩家改写进度"的漏洞形状）。
- `test/accounts.mjs` 88 项：**账号内核与防护规则**。纯逻辑、注入假时钟与内存存储，所以能跑到边界而不靠等。
  A 段先量量具：同一密码两次注册 salt/hash 必须都不同（salt 写死就是"彩虹表一次算好打穿所有人"）；
  **A11/A12 是这份文件里唯一不能注入低配参数的两条** —— 它们量的是"生产参数下一次哈希真的慢"
  （N=2^15、每次吃 32 MiB），反证臂是把 N 改小、这两条立刻红。
  B 段：令牌在库里只有 sha256 没有原文，且配一条"那一格确实是它的 sha256"的反证臂
  （否则 B3 的绿可能只是因为"压根没存"）。C 段整段只挡一件事 —— 把登录接口变成**账号枚举器**：
  不存在的呼号与密码错必须返回同一句话（**C4 量耗时**：两个分支的耗时比 < 2.5×，
  而"用户不存在时也跑一次真哈希"那一行删掉比值会跳到 50 倍以上）。
  E 段是限流与退避：E8 量**指数**（线性退避试 1000 次也就等 1000 秒，脚本等得起），
  E10 量**退避时长不会因为对方继续打而变长** —— 这条红的形状叫 account lockout DoS，
  即"攻击者用自己的请求把受害者永久锁在账号外面"；E13 量并发闸门（32 个并发注册恰好放行 8 个、
  其余当场拒而不是排队），因为密码哈希吃的是 libuv 线程池，而线程池同时还要服务静态文件。
  F 段是呼号白名单：零宽字符、换行、双向覆写符、全角写法（NFKC 之后是同一个 key）逐条拒。
  H 段把同一份逻辑换到 SQLite 后端上再跑一遍（H13/H14）—— 一份逻辑配两个后端，比"测试里抄一份"可靠。
  有三条判据**量不了耗时，只能审计源码**（D5~D7）：邀请码不许用 `===` 比、必须用 `timingSafeEqual`、
  **全模块不许出现 `scryptSync`**。最后那条是这个模块里最要紧的一条：同步哈希会把事件循环停住 ~100 ms，
  而同一个进程里跑着 60 拍/秒的权威 sim —— 它的红不会以任何别的形式出现（不崩、不错、功能全对，只是所有房间一起掉拍）。
  第一版 D5 写成了"两个方向的耗时比值 < 3"，那是**恒真绿灯**：11 字节的字符串比较在测量噪声以下，
  比值在 0.5~2 之间乱跳，永远不会红。
- `test/hardening.mjs` 82 项：**外围闸门**，全部走真 HTTP 与真 WebSocket 握手，不打桩。
  和上一份分工是"规则 vs 接线"：只做 `accounts.mjs` 的话会出现"规则全对、但接口根本没调它"这种绿。
  A 段量的是两条**能被客户端读到的策略格**：`/api/me` 在没登录时回 **200 + `loggedIn:false`**（而不是 401，
  理由见下文"账号状态是按需拉的"那一节），以及 `/api/status` 的 `requireAccount === true`
  —— 后者配 A1b 与 G1 互为反证臂：A1b 要它默认是 `true`，G1 在 `REQUIRE_ACCOUNT=0` 的服上要它是 `false`，
  两条一起红才算真的把那一格量住了（只写一条的话，写死成常量的实现也能全绿）。
  A9/A11 量的是"没登录时那三个字段的形状"：`loggedIn:false` + `name:null` + `profile:null`，
  理由同前 —— 安全属性在 `loggedIn` 那一格，不在状态码上。
  B 段把接口当攻击面：方法白名单（405 + `Allow`）、`content-type` 必须是 JSON（415 —— 这就是 CSRF 的第二道闸，
  跨站表单那条路在预检上过不去）、body 上限（服务端 `tooLarge` 计数 + 客户端看到 413 或明确断开）、
  **畸形 URL `/%` 不许把进程带走**（`decodeURIComponent('%')` 抛 URIError，而 `createServer(handler)`
  不理会 handler 返回的 promise ⇒ unhandledRejection ⇒ Node 15+ 默认整个进程退出；
  也就是 `curl 'http://这台服务器/%'` 一行就能打死对局服务，已修，B9~B11 钉住它）、
  编码过的四种目录穿越都出不了站点根（外加一条"响应体里没出现 win.ini / /etc/passwd 的特征串"，
  因为只看状态码的话"穿越成功但那个文件恰好不存在"也是 404）。
  C 段是长连接：没登录连 WS 直接被握手拒（**在 upgrade 那一刻**，不是"先放进来再在 join 里说不行"）；
  同一账号在两个连接上 join 时自报假名字，**别人看到的仍是会话里的呼号**（C7 是这条的反证臂）；
  每 IP 连接数上限（含"关掉一条之后名额回来了"这条反证臂 —— 不加它的话连接数会单调上涨、越用越少）；
  消息洪水被 1008 拆掉（`WS_MSG_PER_SEC`，正常客户端 60 帧/秒到不了）；建房配额被拒而**进已有房间不受影响**
  （配额管的是"建"不是"进"，反了的话玩家第二局就进不去自己刚开的那间房）。
  D 段单独起一个低配服量限流窗口，并配一条"注册被限流时同 IP 的正常登录不受影响"（两个窗口必须分开）。
  E 段不跑服务，直接造一个权威房间量**对局结果批次的形状** —— `endMatch` 不在 tick 里写账号，
  只把名单挂到队列上（访客不进档案、XP 来自权威 `score`、排干语义、队列有上限）。
  F 段单独起一个 prod 服：`package.json` / `server/` / `.git` / `test/` 全部 404，
  而 `js/` 与首页必须仍然 200 —— 后一条是反证臂，它红了就说明所谓"安全"其实是"整个站都挂了"。
  G 段单独起一个 `REQUIRE_ACCOUNT=0` 的服，量**访客可玩**那一支（8 条）：G2 无会话能进房、G3 自报呼号成为显示名、
  G4 取来注册那条路被拒时的**原话**（不是自己抄一遍，是从 `NAME_RULE_TEXT` 取得），
  **G5 比"两条路上的那句拒绝文案逐字相同"** —— 这条是"一处定义两边共用"的判据，堵的就是"HTTP 层与 WS 层各写一份"，
  红了说明文案已经分叉（用户会在注册页看到一句、在进房时看到另一句）；G6 非法呼号**进不去**（不静默改成"访客"）、
  G7 没带名字才按"访客"进（"忘填"≠"填错"）；G8 量的是访客可以随意开新房 —— 这是**已知被放弃的一项**，
  写成判据是为了让"放弃"这件事有据可查，而不是被人当成漏测。
  H 段量**生产模式的配置闸**（6 条），起因是一个只有部署时才发作的静默失效：`JOIN_CODE` 不设时
  取源码里那个公开的默认值，而日志只说"已设" ⇒ 忘了设的人看到的是"已配好"。
  这一段是这份文件里唯一**预期起不来**的用例，所以它自带一个 `bootRaw()`：拿"它自己退了"这件事
  必须拿到退出码，而 `with-server.mjs` 在服务没起来时会抛异常、退出码就丢了。
  每一条"拒绝"都配一条反证臂：H1 未设就退 / H2 设了就起 / H3 显式设空也起（真的成了开放注册）/
  H4 要账号却没设库就退 / H5 显式 `REQUIRE_ACCOUNT=0` 就放行 / H6 开发模式不许被卡住、

  也能全绿 —— 那是把服务整个焊死。**

### 还没做完的部分（部署前请看一眼）

1. **账号与存档（已收口，本轮）**：以前进度写在浏览器 `localStorage` 里，换台机器就没了，也没有身份 ——
   而"没有身份"这件事的后果不是"不方便"，是**服务端看不见谁在作弊**（自瞄、改自己那一侧的模拟），
   想封人都无处记录。现在有了。

   **入门槛的两个选择，各自的成因写在这里**：
   - **邀请码**（`JOIN_CODE`）而不是图形验证码/邮箱验证。要挡的是**质量**不是**数量**（一个人开 200 个号占房间、
     刷榜），而邀请码把"刷"的单位成本从"一次 HTTP 请求"抬到"搞到一个邀请码"，边际收益比验证码高，
     还不会挡住真正想进来玩的朋友。邮箱验证要接 SMTP，多一个外部依赖和一批投递失败要处理，在公开运营之前不值得。
   - **进对局需要账号**（`REQUIRE_ACCOUNT=1`）。放开成访客可玩只需要一个环境变量，但那样账号之后的所有东西
     （战绩、封人、配额）都会跟着失效，所以默认是关的。**这一条和邀请码是两件事**：邀请码管"谁能注册"，
     这一条管"没注册能不能玩"。

   **令牌放 HttpOnly cookie，不放 Bearer + 前端存储。** 两条路都能用，差的是被打中之后对方能拿走什么：
   任何一次 XSS 都能读走前端存储里的令牌，而这是个游戏 —— 呼号会进记分板、进 HTML。代价是要自己挡 CSRF，
   而这一侧是**结构性**的，不靠"记得加 token"：`SameSite=Lax`（跨站 POST 不带 cookie）+
   只收 `content-type: application/json`（非简单请求 ⇒ 必然先走 OPTIONS 预检，而我们不给任何 CORS 头）+
   方法白名单。附带好处很关键：**WebSocket 握手会自动带上这个 cookie**，于是服务端能在 upgrade 那一刻
   就把身份钉死 —— 而不是等 join 帧里自报一个呼号（要账号的服上 `name` 这一格完全不被读，
   `test/hardening.mjs` 的 C7 就是这条的反证臂：故意在 join 里报"冒充者"，别人看到的仍是会话里的呼号）。

   **呼号只有一个来源，但它有两种情况，判据只有一处**（`server/net-server.mjs` 的 `joinName`）：
   要账号的服上来自会话；**访客可玩的服上（`REQUIRE_ACCOUNT=0`）没有会话可依，自报呼号是唯一的来源，
   但它仍然要过注册用的同一个白名单**。两套规则各写一份的症状是"注册时不让叫的名字，访客模式能叫得出来"，
   而这两种名字进的是同一个记分板。不合法的自报呼号**不静默改成"访客"**：那会让玩家看到
   "我明明填了名字，进去却叫访客"，而"被改掉了"和"没生效"是同一副长相 —— 直接拒绝进场并说明规则
   （`test/hardening.mjs` 的 G5 比的是**两条路上那句拒绝文案逐字相同**，堵的就是"各写一份"）。
   没带名字（手写 `?online=1` 的、老客户端）不算错，按"访客"进：那不是攻击，只是没填。
   **访客模式已知被放弃的一项**：建房配额按账号算，访客没有账号 ⇒ 那条配额在访客模式里是空转的
   （G8 把这件事写成判据，免得以后有人把它当 bug 去查）。

   **密码与令牌用了两种哈希，这是有意的**：密码走 `crypto.scrypt`（N=2^15、每次吃 32 MiB），
   **故意慢、故意吃内存** —— 它做的正是撞库的人想做的事；令牌走 sha256 快哈希，因为它是 256 位均匀随机、
   没有"弱口令空间"可枚举。**并且必须是异步 `scrypt` 而不是 `scryptSync`**：同步版会把事件循环停住 ~100 ms，
   而同一个进程里跑着 60 拍/秒的权威 sim —— 100 个人同时登录就是把所有房间停 10 秒。
   这比"一个人狂发输入帧"狠得多，而且长得完全不像攻击（就是一次登录高峰）。这条没有任何别的表现形式
   （不崩、不错、功能全对），所以它是一条**审计源码**的判据（`test/accounts.mjs` 的 D7）。
   代价是它吃 libuv 线程池（而线程池同时服务静态文件），于是还有一个并发闸门：宁可当场拒"服务器忙"，不排队。

   **"这个呼号存不存在"不许泄露**：`bad_credentials` 一句话同时覆盖"没这个人"和"密码错"，

   于是权威循环看不到任何磁盘延迟，代价是进程被杀最多丢 250 ms 的写入 —— 这条立账写在 `server/store.mjs` 的文件头。
   **不要**设计"客户端上报本局得分"那种接口，那等于把刚堵上的口子重新打开。

   `Δpos≈[-1.187,0,-0.62]`，且客户端补演高达 3282 拍/把）。写回之后：拍号最优 offset 分布从

   等于每次回滚都把账本整体往前挪 `rep` 拍，下一次从这一格出发再补一遍，就再超一遍。实测的形状

   按定义本该差 `rep` 拍。删掉这一行（正确的写法就是**不写**：`start` 那一刻的状态已经在
   `applyJournal` 里恢复过，权威读数给的是 `start+rep` 那一刻的，对它没有新信息）之后：
   稳态最大 0.4415 → 0.1492 m，`repForgotten` 176 → 0，补演 3396 → 54 拍。守卫是 C7。
   **同一轮还撤回了 b3e25b6 对 `rep` 的改法**（那是在上面这个洞没找到的时候打的补丁，教训是
   "别为了让红变绿去改计数器"）：把归零点挪到广播之后，持续饥饿时每份快照只报这一窗的 3 拍、
   而客户端每拍都从同一个基态重算，偏差就按 0.2236 m（= 4.46 m/s × 3 拍）为单位一路累积到 1.56 m。
   恢复"ack 之后的末尾连拍"，并把守卫改成判**形状**而不是判有无：单窗缺口 ≤ 一份快照拍数，
   超了就是在累积必须红（当前实测缺口 1~2 拍）。这条形状判据现在同时是"首段空跑补偿到位"的读数。
   **已修 ②（首段空跑，本轮）**：上面那条修完之后剩下的唯一红线是 0.1539 m，归因很清楚 ——
   服务端 `step()` 每步**二选一**：队列有货就消费一条、没有就拿手里那份空跑（`server/room.mjs`）。
   所以两包之间它跑的 `dTick` 步里，空跑可以落在**消费的前面**；而随包的 `rep` 只报"**末尾**连拍"，
   这几拍它报不出来。客户端当时的基态 `journal[ack+1]` 已经把那些消费算进去了，只把 `rep` 补在
   末尾 ⇒ 那几个空跑被排到了消费之后。输入不交换，位置就差整整 `deficit = Δtick − Δack` 拍：
   实测 `0.1539 m ÷ 2 拍 = 0.0770`，而 `4.46 m/s ÷ 60 = 0.0743`，且 `Δpos=[-0.134,0,-0.075]`
   与相邻两拍的差分同向 —— 是"少走了两拍"，不是物理分叉。
   修法：把基线整个挪到 `start − dAck`（= 上一包的 `ack+1`），然后按服务端实际顺序重演
   **lead 拍空跑 → 那 dAck 条真输入 → rep 拍空跑**，总拍数 = `lead + dAck + rep = dTick`，一步不多
   一步不少（`js/net/predict.mjs` 的 `opts.carry`）。`lead` **不需要协议加字段** —— 上一包随快照
   下来的 `rep` 就是"进这一窗之前已欠下的空跑数"，本窗首段 = `deficit − rep`，两项客户端都量得到。
   实测：稳态最大 0.1539 → **0.0109 m**（那族样本 0.1492 → 0.0039 m，判据线 0.12 m）。
   注意它是**逐轮有波动**的，别只记最好那一轮：同日另一轮是 0.0640 m（样本 630）——
   两轮都在判据线的一半以下，而修之前是 0.1539 / 0.4415 这种会压线的量级。
   空跑窗残差最大 0.0055 m、超尺子 0 个，`test/rollback.mjs` 的 C6 在对照里把两条件分开量：
   旧通路 0.1447 m、新通路逐位重合。net-play 为此新立一条量判据：**空跑窗的残差必须小于
   "我自己走一拍"**，尺子是客户端自己量的日记本相邻两拍距离（补漏则残差恰好等于 `deficit` 拍，
   `deficit≥1` 就跨过尺子）。
   这条线**没动过判据线**：0.12 m 仍是 0.12 m，红是修代码修掉的红，不是挪阈值挪掉的。
   残留（已立账，量小）：`dAck ≥ 2` 且空跑夹在两次消费**中间**那种窗形，`lead` 只能把它排在前面，
   而它实际排在中间 —— 差别是"那一点上施加的相邻两拍输入"，对按住不放的走位是零、对正在转视角的
   一拍是亚厘米级。它不可从 `(dTick, dAck, rep, lastRep)` 里分辨出来（要分辨得再要一个字节），
   由上面那条"残差 < 一拍"的判据兜着：超了就红。
   顺带撤回一条**错误归因**：前几轮把这一族说成"补演用的玩法流游标取错了时点（下行里的 `rngState`
   晚了 6~9 拍）"，并据此论证"要么协议 +4 B/实体/快照下发基态游标，要么改折叠拍的手感语义"。
   实测把这个前提否掉了 —— 试过下发基态游标，偏差反而涨到 0.9673 m 且呈 `(rep−3)` 拍线性，
   而"基态游标与客户端日记本里那一格不同"的比例只有 `1/740`：**那个 4 字节是摆设**，因为
   `journal` 从对齐那一刻起就没漂。真正的成因是上面那个"空跑排在消费前面"，`lead` 三项全是
   客户端量得到的量。
   还要把它与下一段的跨引擎分叉区分清楚：这一族是**这份代码**的问题，跨引擎分叉是**引擎**的问题
   （规范允许的实现差异）—— 两者都曾让 0.44 m 这个量级出现，但修法毫不相干，别混成一个数看。
   还有条跨引擎事实值得部署前知道（这一轮把它量实了，并顺手修掉了两个把排查带偏的量具缺陷）：
   **Node 与 Chrome 的 sim 不可能逐位一致，这是规范允许的，不是 bug。** 证据是 `server/xenv.mjs`
   开头的引擎指纹 —— 每函数 3 万次调用的双精度位模式，本机 Node V8 12.4 vs Chrome/153：
   `sqrt/hypot/乘加` 逐位相同（规范要求精确舍入），而 `sin cos tan atan2 asin acos pow(0.8) exp log cbrt`
   共 11 个逐位不同（规范只要求"实现近似"）。`sin/cos/atan2` 是"朝向→移动方向"，`pow(x,0.8)`
   是爆炸伤害 —— 所以两台引擎从某一拍起必然分叉，且换一个浏览器版本就会换个拍号重来。
   实测那场 900 拍：首分歧第 **760** 拍，逐拍错拍 73/900，但**累计抽数 1624 == 1624** ——
   是"离散事件被挪了一拍"，不是分支分叉。世界几何两端是同一份（54 个碰撞体、位置签名一致）。
   这条对部署是好消息：只有服务端（Node）跑权威 sim，浏览器是每 20Hz 被校正一次的客户端，
   跨引擎分叉只表现为"客户端预测的误差下限"，不会让两边状态永久错开。
   两处量具缺陷一并修掉：① 指纹第一版写了 `Math.round(v * 1e9)`，那等于亲手把 ULP 差异抹掉、
   制造出"两台引擎一致"的假象；② `diffTraces` 把**采样点序号**当成了**拍号**报 —— 对局轨迹每
   10 拍才存一个样本，所以它报的 `tick=76` 其实是第 760 拍（本节先前"第 14 拍 / 第 76 拍"
   两处都受这个错标签影响，排查时对着假拍号找过一圈）。
   另外 `js/player.js` 注释里承诺的日记本覆盖率守卫 `test/net-journal.mjs` 从来不存在，补上后
   第一次跑就点出 `dmgMul / loadout / vm` 三个字段没登记归属。
4. **联机规则（已收口，本轮）**：连杀奖励（白磷弹、UAV）、警觉值、战役检查点以前都带着单机假设 ——
   规则长在 `js/mp.js:MPMatch` 里，而那个类把 `game.player` 当成"这台机器上的我"、把 HUD/DOM 当成规则的输出端
   （`document.getElementById` 在服务端会直接炸）。于是联机侧只能**不接**，症状是规则静默失效：
   按 3 呼叫 UAV 没有任何反应，不报错、不崩。
   拆法照 `hitTestPlayer` / `quant` / `codec` 的同一套：**一处定义，两边共用**。
   `js/match-rules.js` 装规则（`StreakBook` 连杀槽、`TickClock` 按拍排程、`MatchRules` 计分/UAV/白磷弹计时/世界标志位、
   `killScore` 分值），`js/combat.js` 装"呼叫之后会发生什么"（`clusterStrike` / `phosphorusSweep`）——
   单机 `MPMatch` 与权威端 `NetRoom` 各持同一份，差别只在表现去哪（前者播 HUD，后者编成事件下发）。
   四处的成因，每一处都是"不做的话有一个说不出来的错"：
   · **`setTimeout` 换成按拍排程**。不只是"权威端要确定性"：单机的 `MPMatch` 在**暂停**期间 `setTimeout` 照跑，
     暂停菜单里按了呼叫，空袭会在暂停的几十秒里自己落完地。按拍排程随 `update` 停，而且判据能靠
     "调 84 次 `step`"确定性地验收。九颗弹的投放时刻**一次排完**（不是第 84 拍的回调里再排剩下八颗）——
     排程器的到期队列是在这一轮走完之后才收新任务的，嵌套排程会让第二颗起整体多等一拍。
   · **呼叫那一位进协议**（见上面《带宽与 CPU》的 `streak` 字节）。服务端只在**真的消费到一条新输入的那一拍**
     处理它：饥饿时它复用手里那份输入空跑，那一份里可能还留着上一次的请求。
   · **UAV / 白磷弹走世界标志位，不扩快照**。`js/quant.js` 的 `WORLD` 那几个位早就定义了，但
     `server/room.mjs:snapshot` 把 `worldFlags` 硬编码成 0 —— 定义在文件里躺了很久，从来没人往里写过东西。
     现在它要处理一件容易被忽略的事：快照头是**一份发给一屋子人**的（不按接收者过滤），
     所以"敌我"必须用两位分开表达（位 2 归 A 队、位 16 归 B 队），客户端按自己 team 查（`js/quant.js:uavBit`）。
     按人各编一份快照是另一条路，但那是每人 20Hz 一次全表编码，256 人的房间里纯属浪费。
   · **哨戒机枪 / 直升机是权威实体，客户端拿的是"不开火的同形副本"**（`Sentry`/`Heli` 的 `opts.dumb`）。
     位置、航线相位、寿命都从事件来（客户端各抽一次的话，两边的直升机不在同一条航线上）；伤害只在权威端算 ——
     少了这个开关两边会各打一份伤害，那不会报错，只会让所有东西都快一倍死，而没人能从那现象里看出原因。
   读数（本轮实测）：`test/mp-rules.mjs` **72 项**全绿（进程内、确定性拍号）；`net-play` 的真浏览器那一节
   证实"按 3 真的走到了服务端"（`calls > 0`，且 `accepted + rejected === calls` 这条**恒等式**成立）；
   `server/net-probe.mjs` / `deploy-probe.mjs` / `gate.mjs` / `xenv.mjs` 仍全绿。上行输入 15 B → 16 B
   （@60Hz 多 0.48 kbps），输入包那份自测跟着印出新包长。
   **仍立账的缺口（都不阻塞，量小且可数）**：
   ① 联机侧还没记**助攻**（单机只给"本机玩家"算，权威端要遍历所有人的受伤表，而 `victim.dmgTaken` 目前只有 `Bot` 有）；
   ② 击杀奖章（爆头 / 远距离 / 双杀…）的分值已统一到 `killScore`，但联机侧只把**总分**发给击杀者，没有逐条奖章的事件；
   ③ 集束空袭在联机里省掉了"手动标记目标"那一次点击（落点改用呼叫者视线前方 22 m）—— 那是输入不同、不是规则不同，
   但同一个按键在两个模式下手感会略有区别；
   ④ 房间目前**不自动放 AI**（真人对真人），群体警戒这条链路是通的，但只有探针在走它（`test/mp-rules.mjs` 的 E 段）。
