# 现代战线 MODERN FRONTLINE

浏览器里运行的现代军事题材第一人称射击（原创致敬作品），Three.js 写成，**不使用任何外部美术或音频素材**：纹理（含法线、粗糙度贴图）、模型、音效全部由程序实时生成。

- 全程仅通过 **Claude Opus 5.5** 的**一轮对话**生成。实机游玩视频：[B 站 BV1poaP6YEKy](https://www.bilibili.com/video/BV1poaP6YEKy)

## 运行

游戏用 ES Module，必须经 HTTP 打开，双击 html 打不开：

```bash
python3 -m http.server 8080          # 单机：http://localhost:8080
npm install && npm start             # 联机：静态资源与 WebSocket 同端口 http://127.0.0.1:8090/
```

运行时依赖只有 `three` 与 `ws`（Node ≥ 20.10）。推荐最新版 Chrome / Edge 并启用独显；帧数偏低可在「设置」里降画面质量。

## 内容

### 战役：行动代号「午夜清道夫」

夜间渗透卡尔达什边境，与布雷克上尉、狙击手渡鸦组成三人小队，7 个阶段：夜视仪渗透（`N`）→ 清除前哨站（可潜行：敌人有「警觉值」，发现需要时间，蹲伏与消音武器更难被发现，被察觉后整组一起警戒）→ 穿越村庄 → 突入大院逐屋清理、击毙高价值目标「铁蝎」→ 按住 `F` 下载情报 → 坚守 90 秒抵挡三波增援 → 东门开直升机撤离。

检查点（死亡按空格原地重来）、三档难度、最佳通关时间记录。

### 多人对战（对战 AI）

- **模式**：团队死斗、占领（A/B/C 三据点）、自由混战
- **地图**：沙丘镇（沙漠白天）/ 寒霜炼厂（暴风雪）/ 霓虹街区（雨夜都市）/ 货柜场（黄昏港口）/ 双丘战区（丘陵正午，**与占领互为专属**）
- **AI**：三档难度，会寻路、找掩体、投雷、夺点，也使用连杀奖励
- **Perk**：3 栏位共 12 项（双倍时间、拾荒者、爆破专家、冷血、强硬路线、火力过载、幽灵、速愈、快手、振奋、静步、高度警觉）
- **连杀奖励**：侦察无人机、集束空袭（手动标记目标）、哨戒机枪、武装直升机、白磷弹，每次选 3 项
- **计分**：击杀奖章（爆头 / 远距离 / 双杀 / 三杀 / 首杀）、助攻、经验值与等级
- **联网对战**跑在真对局服务上（见《实时联机》）。规则与连杀奖励两端共用同一份实现（`js/match-rules.js` + `js/combat.js` 的 `clusterStrike`/`phosphorusSweep`），服务端是唯一裁决者；**集束空袭的选点两端是同一套**（准星落点环 + 左键确认 / 右键取消），差别只在**谁扣槽**：单机本地扣，联机由权威端验完半径再扣 —— 输入相同，裁决者不同。

**占领（dom）规则** —— 参数收口在 `js/match-rules.js` 的 `DOM_*` 常量组（`DOM_WAVE_BY_FLAGS`），两端跑同一份：

- **同心双圈**：内圈 4.5m **强占领**（每人 2 点力，世界里有实体环）、外圈 30m **弱占领**（每人 1 点力，世界里刻意不画，只在**小地图**画虚线圈）。圈里人人出力、不封顶，两队在圈即僵持，空点回退。独占内圈约 17 秒、单人蹲外圈约 33 秒。
- **积分**：每据点每秒 +0.3；开局各 50 分底分，阵营每复活一人 −1 分（钳在 0）；胜利目标 100 / 200 / 500 分三档。
- **波次复活按占有据点数分档**：0 点（只剩基地）5 秒/波、1 点 10 秒、2 点 20 秒、3 点 30 秒。基地与名下每个据点都是复活点、同档各自循环、不管有没有人排都照转 —— 落后方补员更快，压住滚雪球。
- **复活点要亲手选**：dom 里没有个人倒计时与提前部署，也不替人预定复活点。死亡画面必须点卡片或按 `1/2/3` 选据点、`4` 选基地（再选一次取消），不选不部署 —— 等待时换装备、看战场不会被下一波拽走；选完等那个点的下一波**集体部署**，据点落点 = 弱圈内随机可走处。等的过程中那个点被抢走 → 换旗那一拍选点作废，改选后再走。Bot 同规矩（优先排离目标最近的已占点，没有则排基地波）。
- **水圈**：顶部记分板的据点圈水位 = 占领进度、水色 = 正在占领的一方，归谁整圈染谁的底色，僵持时白圈脉冲（联机由 `domFlags` 事件 0.5s 一班供数，单机直接读规则状态）。圈内进度条同口径 —— 我方在占蓝条、敌方在夺红条。

**空中打击可以被打下来**：武装直升机有 8 段命中体（座舱 / 旋翼主轴 / 机身 / 尾梁 / 垂尾）与 600 点机体血量。子弹只造成 35% 伤害（打要害再 ×1.8，约两个弹匣放倒），RPG-7 直击要害一发即毁、非要害打掉八成血；血量低于七成开始冒烟。装甲表与 `takeDamage` 只有一份（`js/mp.js:HELI_ARMOR`），单机与联机权威端用的是同一个类。

### 武器与枪匠

- **12 把枪**：M4A1 / AK-47 / SCAR-H、MP5 / Vector、PKM、M870、SKS、L115A3、M1911 / .357 左轮、RPG-7
- **枪匠**：8 个配件栏位、每把最多装 5 个，属性正负实时对比；3D 模型可拖拽旋转缩放，7 种迷彩（含黄金）
- **配装**：5 套自定义，可改名，也可对局中途更换（下次部署生效）
- **装备**：致命 = 破片手雷（可烹饪）/ 粘性炸弹 / 燃烧瓶；战术 = 闪光弹 / 烟雾弹 / 兴奋剂
- **姿态后坐力**：相对标称后坐 —— 站 ×1.15 / 蹲 ×1.05 / 趴 ×0.5（蹲的收益在命中盒与脚步声那边，不是免费的后坐折扣）；腰射散布另有蹲 0.8 / 趴 0.65 减档。档位表 `js/weapon-state.js` + 判据 `test/stance-recoil.mjs`
- **高倍镜惩罚**：倍率 ≥ 2 的瞄具（热成像 2.5 / ACOG 4 / 狙击 7）满镜后视线缓慢漂移（趴姿减半、移动与腾空加重、出镜净位移归零），连射 adsSpread 按 (zoom−1) 逐发上浮、10 发封顶 —— 全自动配高倍镜不再是激光枪；栓动/半自动因连射计数清零天然不吃扩散

### 画面

PBR 材质 + 实时阴影 + ACES 色调映射，后处理含泛光、调色、FXAA；天气有沙尘 / 暴雪 / 降雨与动态天空；特殊效果为夜视仪、热成像瞄具，以及受伤、闪光致盲、白磷弹的屏幕效果。

## 实时联机

服务端权威：客户端只上报输入，模拟、命中、规则、结算全在 Node 侧跑，20Hz 下发定长快照，客户端做预测 + 回滚重放 + 对账。

### 联网流程

主菜单 → 联网对战，一条 WebSocket 从大厅走到对局，不换页不重连：

1. **注册页（闸）** —— 要账号的服上未注册先到这一屏，办完身份自动前进。与大厅分屏：注册是前置条件，不是大厅的一部分。
2. **大厅** —— 实时房间列表（服务端一变动就推，不轮询）+ 全服聊天；加入 / 快速加入（fill-first）/ 创建房间。房名是显示名，房号另有白名单 `[A-Za-z0-9_.-]`，中文房名由服务端另编一个。
3. **房间** —— 两队座位栏 + 房间聊天 + 准备 / 开始。只有**房主**能开局，条件在服务端：至少 2 个在场者（Bot 算一个）且其余全部已准备 —— 界面置灰与服务端放行问的是同一个函数。房主离开移交给下一个在线的人；地图 / 模式 / 时长 / 胜利目标 / Bot / 补人只有房主能改，开局后改不动。
4. **对局** —— 打完自动回房间，座位保留、准备状态清零，房主可接着开第二局。

**候选值按模式换表**（`js/data.js`）：

- 目标走 `scoreOptions`（tdm/ffa = `MP_SCORES` 击杀数，dom = `DOM_SCORES` 的 100/200/500 分），时长走 `minutesOptions`（tdm/ffa = 3/5/10/15 分，dom = 15/25/35 分 —— 占点从 200 分起步、复活还回吐，3/5 分钟的局刚进入状态就到点）。
- 两端共读，服务端清洗（`server/lobby.mjs` 的 `cleanScore`/`cleanMinutes`），不认的退回按模式的默认：`DEFAULT_SCORE_LIMIT`（tdm 50 杀 / ffa 25 杀 / dom 200 分）与 `DEFAULT_MINUTES`（dom 25 / 其余 10）。
- 值随 `createRoom`/`roomCfg` 进 `beginLive` 的 cfg，并在 `welcome` 里下发。

**地图与模式的专属绑定是双向的**：`MP_MAPS.modes` 缺省 = 全模式可开（双丘战区 `['dom']`），`MP_MODES.maps` 缺省 = 全图可开（占领 `['ridges']`）。选择器按 `mapAllowed` 藏卡片，服务端 `server/lobby.mjs:mapGate` 按同一判据当场拒绝 —— 建房与改设置都要过"改完之后的组合"这道门，两个方向各说各的拒绝话。

**三种模式都可联机（团队死斗 / 占领 / 自由混战）**：可玩性由 `MP_MODES` 的 `net` 标记决定（服务端判得出胜负的那些）。要加一格玩法，先给它在权威端补上胜负判定，再把 `net` 翻成 `true`。

**Bot** 由房主手动加（每队一个「+ Bot」，点那一行即移除，难度三档一起改），或交给**补人**那一档（默认关）：开着时这一间永远是满的 —— 补满到 16、有人离开或打完就补回来、真人进来时 Bot 让位（总数不变）、房主手动减一个就自动关掉补人。Bot 与真人**共用 16 个位置**，`1 人 + 1 Bot` 就能开局。它与连杀奖励那些实体一样是**权威实体**：跑在服务端、编进同一份 25 字节/实体的快照、进记分板、死了自己回来（延迟与单机同一条式子）。名单只在**等待态**能改，开局那一刻被读进 sim。

### 进对局需要账号

`REQUIRE_ACCOUNT=1` 时这不是只把按钮置灰：没会话拿不到 `/api/rooms`（401），WebSocket 握手也是 401；主菜单入口不藏，只标 🔒。`REQUIRE_ACCOUNT=0` 的访客可玩服跳过注册页直接进大厅（本地调试与对战测试走这条）。要账号的原因不是防 DDoS，而是账号是"封人"的前提。

注册要邀请码（`JOIN_CODE`），生产模式下不设它会被拒绝启动（见《环境变量》的配置闸）。也可以给 URL 多开：`?online=1&room=xxx&team=B`（建房可带 `&title=房间名`）—— 但**从大厅开出的是私人房**，手打房号挤不进去；直连路上没有房间，地图由该实例的 `MAP` 决定。URL 里的 `name=` **不再是身份**，呼号由服务端从会话取。

### 协议要点

- **下行快照定长**：头 11 B + 每人 25 B；16 人 @20Hz = **每客户端 65.8 kbps**（`node server/codec.mjs` 自测打印，在 `npm test` 里）。
- **上行输入** 16 B/拍/人，攒一渲染帧一个包。其中 `view`（u16）= **发出这一拍时我屏幕上渲染的是服务端的哪一拍**，延迟补偿需要的全部输入就是它。报拍号而不报"我延迟几拍"，因为后者要把 `INTERP_DELAY` 与本机帧时序折成一个数，于是两端各有一份会各自漂移的延迟模型。拍号每 65536 回绕，服务端按 `cur` 高位拼回绝对拍号。
- `streak`（最后 1 B）= 这一拍按了 3/4/5 哪一个，没按 `0xff`。必须是**按下沿**，服务端才不必再做边沿检测；且只在真的消费到新输入的那一拍处理（饥饿空跑复用的旧输入里可能还留着上次请求）。
- **命中盒只有一处定义**（`js/combat.js:hitTestPlayer`）：服务端当下裁决 / 回溯裁决 / Bot 裁决 / 客户端反馈五处共用。回溯缓冲只存它依赖的那 4 个标量。
- **敌我键只有一个形状**：团队模式 `'A'`/`'B'`，自由混战每人一支独立队 `'P'+cid`（Bot 用同一个分配器取号，永不撞号）。快照那 1 字节的 team 表达不了序号，所以 **FFA 下快照字节不作敌我用** —— 名牌、own/foes 路由、播报前缀、直升机归属一律以 roster / 事件里的原始队键串为准。Bot 在 FFA 下同样重编独立队，否则它终生带着大厅发的 A/B，两营各抱一团、出生点各堆一翼。

### 延迟补偿

三跳各做一件事：① 客户端每拍上报 `view`；② `rewindTick` 过闸 —— 右端是不可伪造的 `lastSnapSent`，左端是 `LAG_MAX_TICKS = 60`（1 秒），四种情况一律拒绝（一份快照都没发过 / 报当下或将来 / 比已发的新 / 超上限）；③ 过闸后从 `PoseRing` 取那一拍的 `[x, y, z, eye]` 交给 `traceBullet` 的 `rewind` 回调。

- **回溯集合里必须有人也有 Bot**：真人环挂在 client 上，Bot 环挂在房间的 `botPose` 表里，同一把尺、同一道窗。少一半的症状是"打真人正常、打移动 Bot 永远偏"。
- **出窗一律拒绝并退回按当下判**，不夹到窗沿：夹了能换成"错得少一点的补偿"，但那是把"我看到的其实是一秒前"抹成一个假的深度。残差记在 `/healthz` 的 `lag.stale` 上，不是静默的。
- `INTERP_DELAY` 不写死 100ms，按快照到达间隔与抖动的 EMA 收放（55–120ms）；`renderTick` 与插值读同一个活绑定，报值与画面永远同一拍。

### 预测与回滚

`js/net/predict.mjs` 收到快照时回滚重放，并把纠正**写回日记本基态** —— 否则下一次回滚落回同批拍会把上次的纠正整个作废。服务端 `step()` 每步二选一（有货消费 / 无货空跑），所以两包之间的 `dTick` 步里空跑可能落在消费**之前**，而随包的 `rep` 只报末尾连拍；客户端按 `lead → dAck 条真输入 → rep 空跑` 的实际顺序重演，恒等式 `applySteps == dTick` 由判据比过。

跨引擎事实：**Node 与 Chrome 的 sim 不可能逐位一致，这是规范允许的**（`sin/cos/tan/atan2/asin/acos/pow/exp/log/cbrt` 只要求"实现近似"，本机实测 11 个函数位模式不同；`sqrt/hypot/乘加` 要求精确舍入，逐位相同）。因为只有服务端跑权威 sim、浏览器每 20Hz 被校正，它只表现为"预测误差的下限"。`server/xenv.mjs` 按引擎指纹自校准成两档。

### 账号与安全的设计约束

- **令牌放 HttpOnly cookie，不放 Bearer + 前端存储**：呼号会进记分板和 HTML，一次 XSS 就能读走前端令牌。CSRF 靠结构性三道 —— `SameSite=Lax` + 只收 `content-type: application/json`（非简单请求必走预检，而不给任何 CORS 头）+ 方法白名单。附带好处：WebSocket 握手自动带 cookie ⇒ upgrade 那一刻就钉死身份。
- **呼号只有一个来源、判据只有一处**（`server/net-server.mjs` 的 `joinName`）：要账号的服来自会话，访客服的自报呼号仍要过同一个白名单。非法自报**直接拒绝并说明规则**，不静默改成"访客"（"被改掉了"和"没生效"是同一副长相）。
- **密码用异步 `crypto.scrypt`（N=2^15，每次 32 MiB），不能是 `scryptSync`**：同步版会停住事件循环约 100 ms，而同进程跑着 60 拍/秒的权威 sim —— 一次登录高峰就把所有房间停住，且不崩、不错、功能全对。令牌用 sha256 快哈希；哈希吃 libuv 线程池，所以另设并发闸门：宁可当场拒"服务器忙"，不排队。
- **"这个呼号存不存在"不许泄露**：`bad_credentials` 一句话覆盖"没这个人"与"密码错"，且用户不存在时也跑一次真哈希（否则两条路径的耗时差就是账号枚举器）。邀请码比较用 `timingSafeEqual`。
- **忘了密码只有一条出路：注册时抄下来的恢复码**（`server/accounts.mjs`）。注册与每次重设各一次性发 5 张 `XXXX-XXXX-XXXX`，库里只留哈希（落在 meta 抽屉里，不动 `users` 表结构）。四条要紧的：
  - **规范化必须做在哈希输入上** —— 字母表去掉 `I L O U`，抄错的 `O→0`、`I/L→1`、大小写与空格都由 `normalizeRecoveryCode` 吃掉，否则码抄得走形就等于作废。
  - 用掉任意一张 ⇒ **整套作废并换发新的一叠**；重设成功 = 一次登录 + **作废该账号全部旧会话**。
  - 这条路与登录**共用同一张限流表、同一句 `bad_recovery`**（"没这个人 / 没码 / 码抄错"三者同貌），且不管命中第几张都跑满 5 次真哈希 —— 提前 `break` 会把"第几张"漏成耗时差。
  - 服主侧只有补发这一个口子：`node server/recover.mjs`（**只能发码，不能设密码**），补发在审计里留一行 `recover:cli_issued`。
- **存档权威在服务端，且写盘不在 tick 里**：`endMatch` 只把名单挂队列，1 秒一轮的 `resultDrain` 在循环外写档。存储 `node:sqlite` 写穿 + 攒批刷盘（每 250 ms 一批），代价是进程被杀最多丢 250 ms。**不要**设计"客户端上报本局得分"那种接口。
- **账号状态按需拉，不在页面启动时问**（`js/main.js` 的 `accountSync`）：`?online=1` 那条不画菜单的路上，页面加载里挤进的两次请求正好落在客户端第 0 拍与权威端 `addClient` 对齐那一瞬，实测会把稳态预测偏差顶高一档。
- 限流按 IP 而 IP 可伪装；`TRUST_PROXY` 是反代**层数**不是布尔，认了没有代理的 `X-Forwarded-For` 等于把限流 key 交给攻击者自己填。

模板在仓库根 **`.env.example`**（含"设错会怎样"）。⚠ 它**不是自动读取的配置**：服务端零依赖、没有 dotenv，要用 `docker run --env-file .env`、compose 的 `env_file` 或 `set -a; . ./.env; set +a` —— "改了 `.env` 却没生效"和"压根没配"在日志里长得一样。

**生产模式的配置闸**：上表两项"必须显式设"的不设就**拒绝启动**（打印出路后退出码 1）。判据是停住而不是警告 —— 警告在 `docker logs` 里活不过三秒；**显式的空值是允许的**，那是"我知道我在要什么"，开发模式两条都不卡但日志必须写明在用默认值。

- 起因是一个只在部署时发作的静默失效：`JOIN_CODE` 不设时取源码里那个**公开的**默认值，而上一版日志只看真值、于是打印"已设"；`ACCOUNTS_DB` 不设 = 内存库，而默认要求登录 ⇒ 进程一重启所有人的账号一起消失，且这件事只在重启后才看得出来。
- ⚠ `ALLOW_ORIGIN` 是例外、也只能是例外：确实存在**不需要**来源检查的部署，所以它不掐服务，代价是它必须喊得比这两条响（生产模式下多行 + 写清后果 + `启动完成` 哨兵收尾）。判据见 `test/hardening.mjs` 的 H7/H8，理由见 `docs/net-vs-local-gaps.md` 附十三。

### 带宽与容量

容量是压出来的，不是算出来的：`npm run soak`（默认阶梯 1 / 2 / 4 / 8 间 × 16 人 = 16 → 128 人；位置参数只认纯数字那一档，`node server/soak.mjs 16` 即 256 人）。也能压远处实例：`--url=https://your.domain` 要的是 **http(s) 基址**（据此 fetch `/healthz`，并把 `^http` 换成 `ws`），要账号的服带 `--cookie=mf_sid=...`。

两个必踩的坑：

- 生产通常设了 `ALLOW_ORIGIN`，而 `ws` 库不发 Origin 头 ⇒ 全部 403（soak 对外部目标默认带"目标自己"这个来源，跨源用 `--origin=`）。
- `CONNS_PER_IP` 默认 6，本机压测所有连接同一 IP，第 7 个就被拒（下表读数用 `CONNS_PER_IP=256` 跑出）。

读数以**服务端自报**为准（假客户端跑在压测进程里，从对面数帧率分不清是服务器慢还是压测机慢）。本机（Windows，单进程）实测：

| 人数 | 间数 | 每间 hz | 每拍耗时 | 落后墙钟 | 下行/人 | 峰值堆 |
| --- | --- | --- | --- | --- | --- | --- |
| 16 | 1 | 60.1 | 0.125 ms | 0 ms | 20.0 Hz | 15.7 MB |
| 64 | 4 | 59.9 | 0.083 ms | 0 ms | 20.1 Hz | 26.5 MB |
| 128 | 8 | 59.3 | 0.064 ms | 0 ms | 20.0 Hz | 25.0 MB |
| 256 | 16 | 59.1 | 0.060 ms | 0 ms | 20.1 Hz | 36.5 MB |

256 人这一档仍未到模拟瓶颈（每拍 0.06 ms，预算 16.7 ms）；压完房间回收后堆回落到 20 MB。

### 反向代理

TLS 交给 nginx / Caddy，`wss` 必须显式转发 Upgrade 头，否则浏览器握手直接失败：

```nginx
location / {
  proxy_pass http://127.0.0.1:8090;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
  proxy_read_timeout 120s;          # WS 空闲期，别用默认 60s 掐断
}
```

`ALLOW_ORIGIN=https://your.domain` 之后别的站点就借不走你的对局服务（WebSocket 不受 CORS 约束，不检查来源等于对所有网站开放）。

### 容器与下线

配置按 `.env.example` 抄一份（改掉 `JOIN_CODE` 与域名），用 `--env-file` 在运行时喂进去 —— **不要把 `.env` 打进镜像**（`.dockerignore` 已挡）。**账号库要挂出来**，否则容器一重建所有人就登不上：

```bash
docker build -t mw-room .
docker run -d -p 8090:8090 --env-file .env -v mw-accounts:/data mw-room
```

- **健康检查** `GET /healthz` → `{ok, rooms, clients, tickHz, uptime, draining, heapMB, per[]}`；`per[]` 逐间报 `hz / stepMs / behindMs / fails`；另有 `lag{…}`（延迟补偿计数）、`streak{}`、`worldFlags`、`gate{}`、`auth.store`、`lobby{}`、`roomDir{}`。Dockerfile 已挂 HEALTHCHECK。
  这些计数存在的理由是一样的：这类失效在玩家侧只表现为"打不中""按了没反应"，运维得能在服务端先看见 —— 比如 `lag` 里没有 `botRewound`/`botPoseMiss` 两格时，"Bot 全部按当下裁决"在 shots/ok 上完全看不出。
- **下线**：收到 `SIGTERM` 先置 `draining`（LB 可据此摘实例），给在册连接发一条带原因的 `note` 并以 `1001` 关闭，停房间循环，在 `SHUTDOWN_GRACE_MS` 内退净。
- ⚠ 上面两条 docker 指令在本机**没跑过**（开发机没装 docker）。不需要 docker 守护进程的那一半已经量了（`test/image.mjs`，在 `npm test` 里）：`COPY` 的源都在仓库里、`CMD` 指着真文件、镜像默认 `NODE_ENV=production`、非 root、运行时导入闭包与 `PUBLIC` 白名单一条都没被 `.dockerignore` 挡住、闭包里没有一处 import playwright。
  HEALTHCHECK 那句 payload 会被抠出来**对一台真服跑**（退出码 0）**再对一个空端口跑**（必须 1）—— 否则它只是个"永远健康"的装饰。
- 剩下没验的就四条：真的 `docker build`、真的 `docker run`、镜像层体积、以及 `SIGTERM` 那段在 **Windows 上没被测过**（libuv 的 `child.kill()` 是直接 TerminateProcess，信号送不进子进程）。Linux 上第四条由 `server/deploy-probe.mjs` 验收。

### 真机部署

按 **`docs/deploy-checklist.md`** 走六节：`npm test` → 起一台生产模式实例 → 远程体检 → 远程压测 → 容器三步 → 上线后要盯的三个数。三个量具都是**从外面看**的（起进程 ≠ 验服务）：

- `node server/remote-probe.mjs --url=http://ip:8090` —— 只读体检（`/healthz` 各字段、静态白名单、来源检查、限流）。要账号的服加 `--invite=<邀请码> --register` 才做会写库的那几笔。生产模式的来源检查是机器可查判据：`gate.originCheck` 自报要与"陌生来源被 403"的实测一致。
- `node server/soak.mjs --url=...` —— 远程容量阶梯，读数仍以服务端自报为准。
- `node server/recover.mjs --db=/data/accounts.db --name=某呼号` —— 忘到"恢复码也没了"时的最后一条路：给这个呼号**补发一叠 5 张新恢复码**（补发即作废旧的那一叠），念给本人。**不能设密码、不能改呼号**，也不打印任何旧码；补发记录在审计里（`node server/audit-dump.mjs --ev=recover:cli_issued`）。

- `test/worker-core.mjs` 同参两次生成逐位一致、同步回退路 19 种 TEX 全就位、`findPath` == `astarPath` · `test/preload-graph.mjs` `modulepreload` 清单必须**等于**源码模块图闭包，并核对生产白名单发得出去 · `test/image.mjs` 容器配方里不需要 docker 守护进程的那一半（`node test/image.mjs A` 分段跑）· `server/xenv.mjs` 按引擎指纹自校准成两档的跨环境一致性

**表现层与手感**

- `test/fps.mjs` 真实客户端那条 RAF 循环的帧率无关性（对照组 `fixedStep=false` 必须漂，否则这把尺子永远绿）· `test/viewmodel.mjs` 视图模型拆分的接缝回归 · `test/gunvisual.mjs` 枪械视觉六条，每条问的都是**被画出来的那个量** · `test/optic.mjs` 开放式瞄具通透性与分划**角直径** · `test/state-leak.mjs` 死亡 / 换局 / 热成像三处的状态残留
- `test/net-feel.mjs` 联机手感层：远端表现 + 本地反馈闭环，共同点是**全都不影响权威状态** —— 少了它不崩不报错，只是"看不见、听不见、没反应"。AA 段是空跑窗尺子自己的判据，V 段是语音播报
- `test/net-play.mjs` / `test/net-drop.mjs`：两个真浏览器对打（延迟补偿与客户端帧时序唯一一起参与的地方）、掉线四种情形分开验收；另外量奖章弹窗、房间屏"补人"那一格、账号闸上的"忘了密码？"
- `test/tab-session.mjs` 同源双标签页（cookie 按"源"共享，两个 page 放进同一个 context）· `test/worker-live.mjs` Worker 双路真浏览器离线实跑，B 臂把 `window.Worker` 封锁死

**要真浏览器**：`xenv` / `fps` / `viewmodel` / `gunvisual` / `optic` / `state-leak` / `net-play` / `net-drop` / `tab-session` / `worker-live` —— 名单**从源码推**（谁 `import { chromium } from 'playwright'` 就是谁），漏写和多写都红。其余判据都在进程内跑完，不碰浏览器。

这 10 份的 `launch()` 都按同一顺序试三档：**系统 Chrome** → **Playwright 自带的那一份**（不带 `channel` / `executablePath`，所以 `npx playwright install chromium` 装的就是它）→ 本机绝对路径。中间那一档是"别人的机器能不能跑起来"的全部依据，由 G 段逐份核（少一档就红）。

## 已知缺口

本表只列部署与账号层面的缺口。联机与本地的手感差距另有一份只读走查清单：`docs/net-vs-local-gaps.md`（45 条 + 每条的判据与收口记录，遗留账汇总表在附十四 / 附十五）。

1. **战役的经验值不进账号**（有意）：单机模拟客户端能自己算，服务端无法验证，报上去等于给了个免验证的加经验入口。这一条以前**不只是"不进账号"，还会被账号抹掉** —— 两半挤在同一个 `profile.xp` 上，任何一次账号同步都把战役那一笔盖成服务端的数，不报错、不崩，只是打完一整场战役回主菜单经验条原封不动。现在分开存（`xp` 账号那份 / `xpLocal` 本地那份），等级按两半之和算，档案卡上分开写；联机记分板那一列读的仍是服务端自报的账号 xp。判据 `test/progress.mjs`。
2. ~~账号自己找不回来~~ 已收口（2026-09-30 · 一次性恢复码）：机制见《账号与安全的设计约束》，设计理由与"能不能红"的三次实测见 `docs/net-vs-local-gaps.md` 附十二。仍未收的那半：没接邮箱/短信，码丢了只能找服主。
3. `ALLOW_ORIGIN` 留空在生产模式下**没有**做成拒绝启动（`JOIN_CODE` / `ACCOUNTS_DB` 那两条做了）—— 确实有不需要浏览器来源检查的部署；它现在由 remote-probe 在部署面上当场点名。
4. 已收口的三条联机表现缺口：**联机结算页**与单机逐格对齐、**击杀奖章**（`killScore` 的 `tags` 随 `kill` 事件逐条发到击杀者，客户端按与单机同一张表逐条弹）、**Bot 自动补人**（补满到 16、有人走就补、真人进来 Bot 让位、手动减一个自动关掉这一档）—— 账见 `docs/net-vs-local-gaps.md` 附五 / 附十。仍然**不做**的：对局中途进人、中途加 Bot（`joinRoom` / `addBot` 在 `stage !== 'waiting'` 时拒收）—— 名单只在等待态读进 sim，这是 `server/lobby.mjs` 写死的前提，不是漏做。
5. **多实例编排**，口径仍然只有一句：**一个进程 = 一个权威端 = 最多 `MAX_ROOMS` 间对局（等待态另给 2× 额度）+ `MAX_CLIENTS` 条连接** —— sim 永远只在它出生的那个进程里跑，《带宽与容量》那张人数表是**每进程**的数。
   - **跨进程房间目录已收（2026-10-01）**：设 `ROOMS_DB` 为多台共享的 SQLite 文件，每台把自己的房间行**自报**进去（自报 + 心跳 + TTL，没有协调者 —— 一台崩了它的行在 TTL 内由任何路过的一台扫掉），于是任何一台上打开的大厅都能看到全部台的房。
     要账号的部署里跨台凭**一次性入场票**：玩家登录的那台验过会话后发票，目标台的 ws 握手那一刻消费 —— 账号账本仍进程私有，票是唯一被带过去的身份。残余风险（有意不改，记档于 `docs/net-sync-audit.md`）：票走握手 URL 的 `?ticket=` query，必然落反向代理 access log 与浏览器历史，泄露面比 HttpOnly cookie 大一截。判据 `test/room-dir.mjs` 三层。
   - **没收**的是相邻那条：多台共用**同一个 `ACCOUNTS_DB`**。探针 `server/multi-account-probe.mjs` 钉着现状（活进程的账本互不可见、同名并发注册两边都成功），成因是 `SqliteStore` 的"开库载入一次 + 读全走内存 + 写攒批刷盘"是进程私有账本（60Hz 的 tick 里不许有磁盘访问）。要收是**架构题**。进程内的并发双花已修（`_keyChain` 每呼号串行，判据 `test/accounts.mjs` L 段），细节见附十五。
   - `?room=` 深链语义不变：它指向的地址就是它要连的那台。多机 / 反代部署每台设 `PUBLIC_URL`，`ALLOW_ORIGIN` 要把**所有实例的页面来源**都列上。用法写在 `docs/deploy-checklist.md` 第 1 节末尾。
6. **仍欠的真机读数**三条：容器那四步（要一台有 docker 的 Linux 机器）、上面那 10 份判据 `launch()` 中间一档的本机实测（先 `npx playwright install chromium`）、跨进程共享账号账本。
   第 10 轮收掉的四件（空跑窗尺子在静止时退化 `js/net/idle-ruler.mjs`、`test/image.mjs` 的段过滤器、未补偿空跑窗的分布测量、跨进程房间目录）与每条的"现在什么状态 / 为什么停在这 / 下一轮第一步 / 今天能不能被机器看见"都在附十四 / 附十五那张表里。
   同一节末尾另有一份**"别把这些当成遗留"**（战役经验值不进账号 / 对局中途不加人 / `ALLOW_ORIGIN` 不拒绝启动 / 恢复码不接邮箱 / "补人"默认关）—— 它们是有意的，不是没做完。
