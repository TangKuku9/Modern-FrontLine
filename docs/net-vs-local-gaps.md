# 联机对局 与 本地对局 的体验差距清单

调研对象：`js/`（客户端与共用的 sim）+ `server/`（权威端）+ `js/net/`（联机表现层）。
方法：只读走查，全部结论附 `文件:行号`；高影响项逐条回读源码复核（见《附一 · 证据等级》）。
本文只列差距，不含修法。

---

## 结论

联机和本地**不是同一套玩法少收了几处**，而是**三条不同的缺失链**同时存在，且互相放大：

1. **内容/规则层**被砍到只剩一小半 —— 3 种模式剩 1 种、连杀奖励不能自选、局内不能换职业、不能捡枪、助攻没有、没有结算页。
2. **世界实体层根本不在协议里** —— 别人的手雷/燃烧瓶/闪光/烟雾/RPG 弹既不存在于快照，也没有对应事件。玩家看到的是"血条突然掉一截"，不是"我被炸了"。
3. **远端玩家的表现层几乎是空的** —— 位置插值在跑，但开火没枪声没曳光、脚步没声音、受击没反馈、死亡没提示。数据到客户端了，没人画。
4. **本地玩家自己的反馈闭环断了** —— 击杀播报、死亡画面、受伤方向、痛感音，四处都没接线（`onNetKill`/`onNetDeath` 在 `js/main.js` 里不存在）。

按玩家感知排序，最刺眼的三条是：**听不见别人（第 20 + 21 条）**、**打死了没有任何提示（第 31 + 32 条）**、**手雷看不到（第 12 条）**。

## 三、远端玩家的表现层：数据到了，没人画

## 附一 · 证据等级

以下 16 条我在本轮**逐条回读源码/亲手 grep 复核**过（不是只看走查笔记）：

`1`（部分）、`4`（`resolveStreaks` 无调用方）、`7`（服务端无 scavenger/quickfix 分支）、`8`、`12`、`13`、`14`、`16`、`20`、`21`、`22`+`23`（按三处约定交叉推导）、`24`、`25`、`27`、`31`+`32`、`33`、`37`、`38`、`42`。

其中第 22 / 23 条（朝向 180° 反 + 俯仰符号反）是**推导**而非目视：三条独立约定互相印证（模型正面在 -Z、`forward` 公式、第一人称相机 `rotation.y = aimYaw`），本地 AI 与它们一致，只有远端那两行是异类。**动手前建议按 §附二 的方法做一次目视确认** —— 这个仓库里"形状自洽但归因错"有过先例。

## 附二 · 本仓库标准的验法（负对照）

- 朝向 / 重生后姿态：开两个窗口，对面**朝你跑并停在正前方**、再**死一次重生**，看是否背对 / 是否一直躺着。
- 投掷物隐形：对面扔一颗手雷到你脚边。若只有血条掉、没有飞行物与爆炸 ⇒ 成立。
- killfeed / 死亡画面：`js/main.js` 里搜 `onNetKill` / `onNetDeath` 无定义即可判定，无需实机。
- 燃烧瓶零伤害：`server/stubs.mjs` 的 `EFFECT_OVERRIDES` 里 `effects.addFireSource` 返回假对象、且服务端 step 无 `effects.update` ⇒ 回调不可能被跑到。

### 下半场（同一轮）：第 5 行也收了 —— 跨进程房间目录与派发

附十四第 5 行的原话是"功能缺口，不是判据缺口 —— 没有'再补一条判据'就能收的形状，先定目录放在
进程外的哪里，再决定 `?room=` 怎么解析"。这一轮把两个决定都做了，并整条收掉：

| 决定 | 收法 | 为什么是这个收法 |
|---|---|---|
| 目录放在**进程外的哪里** | 一个**多台共享的 SQLite 文件**（`ROOMS_DB`），`server/room-dir.mjs`：每台把自己的房间行**自报**进去，心跳续租、超时即死，**没有协调者** —— 一台崩了，它的行在 TTL 内由任何路过的一台扫掉，不需要谁去"接管" | 这个仓库的部署面是零依赖的（node:sqlite / ws / three，没有 redis），引入任何"目录服务"都是新的运维面；而共享文件 + 租约正是容器编排里同一问题的最简形状。写入**直写**、不走账号那套攒批 —— 探针量得很清楚（S1），账本进程私有的根因就是"载入一次 + 内存读"；目录的每笔都小、频率被心跳压着，而它的全部意义就在于"别台马上要看见" |
| `?room=` 怎么解析 | **不变** —— `?room=` 指向的地址就是它要连的那台（深链本来就带着 host:port）。跨台的需求由**大厅列表**承担：任何一台上打开的大厅都列全部台的房（带"另一台"标记与那台的 url），点谁的房就连谁的台；快速加入在本台没有可进的等待房时也跨台 | `?room=` 是"我把某个地址+房号发给朋友"的形状，它天生带着地址；给深链再做一层全网解析，等于给一个已经自含答案的问题加一次查询。列表才是"我连这台上，但想打别台的房"的场景 |
| 账号怎么办（部署里绕不开的一格） | **一次性入场票**：玩家在 A 台验过会话（登录态在那台上），点 B 台的房时 A 台发一张票进目录（目标必须是目录里登记的另一台、票只带 key/呼号/XP、单次有效、`ROOMS_TICKET_TTL_MS` 内有效），B 台在 ws 握手那一刻消费它。目录没开的台 `/api/dispatch` 404 | 账号账本**进程私有**是上面探针钉着的立账红 —— 本轮不收它，但默认部署（`REQUIRE_ACCOUNT=1`）下没有票的跨台加入会在 B 台闸上 401，功能对默认部署就是死的。票与一次成功登录能建立的身份等价、单次有效、短 TTL —— 偷到票的窗口与偷到会话 cookie 同阶，没有引入新的信任级；"目标必须在目录里"挡住"把登录身份转发到任意地址"的代理化滥用 |
| 客户端怎么换台 | 换台 = **换一条连接**（`main.js onlineLobby(url)` 参数化 + `menu.remoteJoin`）：大厅 → 房间 → 对局都走同一条 ws 是 `js/net/lobby.mjs` 写定的前提，旧连接上的座位/房间状态随拆连接作废 | 在旧连接上"代理"别台的帧等于把一个进程变成另一个进程的网关 —— 延迟、复杂度、以及"两个权威端对同一连接都有话说"的串门形状，全是要躲的 |

判据分三层（`test/room-dir.mjs`，31 条，都在主体档里）：

- **单元**（注入时钟，不等真实时间）：diff 语义（内容没变的重发不算变 —— 心跳不推屏；人数变了才算 —— 这就是跨台人数传播的机制）、TTL 扫除、同 id 两行并存（dkey = boot:id，各带各的 url）、门票消费一次给出身份【反证：第二台再消费拿不到】、过期即拒。
- **访客双机集成**：两台真服务共享一个目录文件 —— 发行可见（`/api/rooms` 与 ws 大厅帧同一份名单）、跨台真进得去、人数即时传播（pushLobby 钩子，不等心跳）、整台被杀后行在 TTL 内消失；反证臂：**不开 `ROOMS_DB` 的台**它的房不上榜、`/api/dispatch` 404 —— 缺省部署行为不变是被判据钉着的，不是口头承诺。
- **账号票链**：没会话 401【反证】、目标不在目录 400【反证】、凭票握手放行且身份是票上的呼号（join 不看自报的 name）、**用过的票再握手 401**【反证】、**过期的票 401**【反证】。

"能不能红"两次实测（都按 SHA256 还原）：把"消费即销核"拆掉 ⇒ `RED 29/31`，红的正是"用过的票再握手"与单元反证那两条（重放的握手被放行）；把 TTL 扫除关掉 ⇒ `RED 29/31`，红的正是"整台崩了行要消失"的集成格与单元 TTL 格。

运维面上的三件：`/healthz` 的 `roomDir` 格自报（开着没开、对外 url —— 地址错了的症状是"列表里有别台的房、点进去连不上"）；`PUBLIC_URL` 未设时启动日志点名（反代/跨机器必须显式设）；`ALLOW_ORIGIN` 要把**所有实例的页面来源**都列上（跨台握手时 Origin 是玩家所在那台的 —— 这一句写进了 README《环境变量》与部署清单 §1）。
